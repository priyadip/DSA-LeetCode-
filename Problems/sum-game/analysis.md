# 1927. Sum Game - Solution Analysis

## Problem Understanding
Alice and Bob alternately replace '?' in a string of even length with digits 0–9. Alice starts. Bob wins if the final sum of the first half equals the sum of the second half; otherwise Alice wins. Both play optimally. The input length is up to 10⁵, so an O(n) solution is required. The outcome is determined solely by the initial difference of known digits and the counts of '?' in each half.

## Approach
The solution uses a **game theory / greedy** insight. Let `d = sum_left_known - sum_right_known`, `l = number of '?' in left half`, `r = number of '?' in right half`. Each '?' in the left half can add 0–9 to the difference, each in the right half can subtract 0–9. Because players alternate and Alice moves first, Bob can force the final difference to zero **iff** the initial difference `d` exactly equals the “midpoint” of the total adjustable range, i.e. `d = 9*(r - l)/2`. Equivalently, Bob wins exactly when `2*d == 9*(r - l)`. The algorithm computes `d`, `l`, `r` in one pass and checks this condition.

## Algorithm
1. Let `n = len(num)`, `h = n // 2`.
2. Initialize `d = 0` (difference left_sum – right_sum), `l = 0` (left '?' count), `r = 0` (right '?' count).
3. For each index `i` and character `ch` in `num`:
   - If `ch == '?'`: increment `l` if `i < h` else increment `r`.
   - Else: if `i < h` add `int(ch)` to `d`; else subtract `int(ch)` from `d`.
4. Return `True` (Alice wins) if `2*d != 9*(r - l)`, else `False` (Bob wins).

## Line-by-Line Explanation
- `n = len(num)`: total length.
- `h = n // 2`: half length, splits the string into two halves.
- `d = l = r = 0`: initialise difference and question-mark counters.
- `for i, ch in enumerate(num):`: single pass over the string.
- `if ch == '?':`: count question marks per half.
- `if i < h: l += 1 else: r += 1`: left half indices `< h`, right half `>= h`.
- `elif i < h: d += int(ch)`: known digit in left half increases the difference.
- `else: d -= int(ch)`: known digit in right half decreases the difference.
- `return 2 * d != 9 * (r - l)`: Alice wins unless the Bob‑win condition holds exactly.

`2*d = 18`, `9*(r-l) = 9*2 = 18`. Condition holds → return `False` (Bob wins). Matches example.

## Complexity
- **Time:** O(n) – one linear scan over the string.
- **Space:** O(1) – only a few integer variables used.

## Edge Cases
- **No '?'** (`l = r = 0`): condition reduces to `d == 0`. If sums already equal, Bob wins (return `False`); otherwise Alice wins (return `True`). Correct.
- **All '?'** (`d = 0`, `l = r = n/2`): `r - l = 0`, condition `0 == 0` holds → Bob wins. With even total moves, Bob can mirror Alice’s moves to keep sums equal.
- **Large input** (n = 10⁵): O(n) time and O(1) space easily fit limits.
- **Negative `d`**: The formula works with negative differences because both sides scale linearly.

## Possible Improvements
The solution is already optimal in both time and space for the given constraints. The formula is a direct, constant‑time evaluation after the counting pass. Variable names (`d`, `l`, `r`) are concise but could be renamed to `diff`, `left_q`, `right_q` for readability; however, this is a minor stylistic point and does not affect correctness or performance.
