# 11. Container With Most Water - Solution Analysis

## Problem Understanding
Given an array `height` where each element represents a vertical line at index `i` with height `height[i]`, find two lines that form a container with the x-axis holding the maximum water. The container's area is width (distance between indices) multiplied by the minimum of the two heights. Constraints: `n` up to 10^5, heights up to 10^4, so O(n^2) brute force is infeasible; O(n) or O(n log n) required.

## Approach
**Two-pointer greedy**. The brute force checks all O(n^2) pairs. The key insight: starting with the widest container (leftmost and rightmost lines), moving the pointer at the shorter line inward is the only way to possibly find a larger area, because width decreases monotonically and the shorter line caps the height. Moving the taller line cannot increase the area since the height is still limited by the shorter line and width only shrinks. This greedy choice is safe and yields O(n) time with O(1) space.

## Algorithm
1. Initialize `i = 0` (left), `j = len(height) - 1` (right), `ma = 0` (max area).
2. While `i < j`:
   a. Compute width `d = j - i`.
   b. If `height[i] < height[j]`:
      - Area `ar = height[i] * d`.
      - Increment `i` (move shorter left line rightward).
   c. Else:
      - Area `ar = height[j] * d`.
      - Decrement `j` (move shorter right line leftward).
   d. Update `ma = max(ma, ar)`.
3. Return `ma`.

## Line-by-Line Explanation
- `i, j, ma = 0, len(height) - 1, 0`: Initialize left pointer, right pointer, and max area tracker.
- `while i < j:`: Loop until pointers meet; every pair is considered exactly once.
- `d = j - i`: Current width between lines.
- `if height[i] < height[j]:`: Compare heights to decide which pointer to move.
- `ar = height[i] * d`: Area limited by left line (the shorter one).
- `i += 1`: Move left pointer inward; any container with the old left line and a line left of `j` would have smaller width and same or smaller height.
- `else:`: Right line is shorter or equal.
- `ar = height[j] * d`: Area limited by right line.
- `j -= 1`: Move right pointer inward for the same reasoning.
- `if ar > ma: ma = ar`: Update maximum area if current is larger.
- `return ma`: Final answer after exhausting all candidate pairs.

## Complexity
- Time: O(n), where n = len(height). Each iteration moves one pointer inward; total iterations ≤ n-1.
- Space: O(1). Only a few integer variables used regardless of input size.

## Edge Cases
- **Two elements** (`n=2`): Loop runs once, computes correct area, returns it.
- **All equal heights**: The `else` branch always executes (since `height[i] < height[j]` is false), moving `j` leftward each step; still evaluates all widths with that height, finds max at first iteration (widest).
- **Strictly increasing heights**: Left pointer moves right each step; correctly evaluates containers anchored at each left index with the farthest right.
- **Strictly decreasing heights**: Right pointer moves left each step; symmetric.
- **Zero heights**: Area becomes zero when a zero-height line is the shorter; pointer moves past it, no issue.
- **Maximum constraints** (`n=10^5`): O(n) loop with simple arithmetic fits easily within limits.

## Possible Improvements
The solution is already optimal in time (O(n)) and space (O(1)) for this problem. The commented-out alternative uses `min` and `max` built-ins which are marginally slower due to function call overhead but clearer; the current inline version avoids that overhead. Variable names `i`, `j`, `ma` are terse but standard for two-pointer patterns; renaming to `left`, `right`, `max_area` would improve readability without changing complexity.
