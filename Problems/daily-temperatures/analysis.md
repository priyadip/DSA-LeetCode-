# 739. Daily Temperatures - Solution Analysis

## Problem Understanding
Given an array `temperatures` where each element represents the temperature on a given day, we must return an array `answer` where `answer[i]` is the number of days to wait after day `i` for a strictly warmer temperature. If no warmer day exists, `answer[i]` is 0. The constraints (`1 <= n <= 10^5`, temperatures in `[30, 100]`) require an O(n) or O(n log n) solution; a naive O(n²) scan would time out.

## Approach
The solution uses a **monotonic decreasing stack** (storing indices). This pattern suits "next greater element" problems where we need the distance to the next larger value. The brute force would, for each day, scan forward until a warmer day is found — O(n²) time. The monotonic stack processes each index once: indices wait on the stack until a warmer temperature arrives, at which point they are resolved in LIFO order. The key insight is that once a warmer temperature appears, it resolves all previous cooler days that have not yet found a warmer day, and those cooler days will never need to be checked again.

## Algorithm
1. Initialise `answer` array of zeros with length `n`.
2. Initialise an empty stack to hold indices of days whose warmer day has not yet been found.
3. Iterate `i` from 0 to `n-1` with current temperature `temp`.
4. While the stack is not empty and `temperatures[stack[-1]] < temp`:
   - Pop the index `prev` from the stack.
   - Set `answer[prev] = i - prev` (the distance to the current warmer day).
5. Push current index `i` onto the stack.
6. After the loop, any indices left in the stack have no warmer future day; their `answer` entries remain 0.
7. Return `answer`.

## Line-by-Line Explanation
- `answer = [0] * len(temperatures)`: Pre-allocate result array; default 0 handles days with no warmer future.
- `stack = []`: Stack will store indices of days waiting for a warmer temperature, maintained in decreasing temperature order.
- `for i, temp in enumerate(temperatures):`: Single pass over the array.
- `while stack and temperatures[stack[-1]] < temp:`: Current day is warmer than the day at the top of the stack; resolve those waiting days.
- `prev = stack.pop()`: Retrieve the index of the cooler day that now finds its warmer day.
- `answer[prev] = i - prev`: Distance in days between the cooler day and the current warmer day.
- `stack.append(i)`: Current day becomes a candidate for future warmer days.

## Complexity
- Time: O(n), because each index is pushed onto the stack exactly once and popped at most once; the while loop across all iterations performs at most n pops total.
- Space: O(n), for the `answer` array and the stack, which in the worst case (strictly decreasing temperatures) holds all n indices.

## Edge Cases
- **Single element** (`n=1`): Loop runs once, stack gets index 0, no pops occur, `answer` remains `[0]` — correct.
- **Strictly increasing temperatures** (e.g., `[30,40,50,60]`): Each new temperature immediately pops the previous index, producing `[1,1,1,0]`.
- **Strictly decreasing temperatures** (e.g., `[90,80,70]`): No pops ever occur; stack grows to size n, all `answer` entries stay 0 — correct.
- **Duplicate temperatures**: Condition uses strict `<`, so equal temperatures do not resolve each other; the later equal temperature stays on top, waiting for a strictly warmer day — matches problem requirement.
- **Maximum input size** (`n=10^5`): O(n) time and space fit comfortably within limits.

## Possible Improvements
The solution is already optimal in both time and space for the given constraints. The monotonic stack achieves the theoretical lower bound of O(n) for this problem. Variable names (`answer`, `stack`, `prev`) are clear and idiomatic. No redundant passes or structures exist. No further improvement is needed.
