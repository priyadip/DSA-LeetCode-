# 115. Distinct Subsequences - Solution Analysis

## Problem Understanding
Given strings `s` and `t`, count how many distinct subsequences of `s` equal `t`. A subsequence preserves relative order but not necessarily contiguity. The answer fits in a 32-bit signed integer. Constraints: `1 <= len(s), len(t) <= 1000`, English letters only. The lengths rule out exponential enumeration; a polynomial DP is required.

## Approach
**Dynamic Programming (space-optimized 1D DP).**  
The brute force would explore all `2^n` subsequences of `s`, which is infeasible for `n=1000`. The classic 2D DP defines `dp[i][j]` as the number of ways to form `t[:j]` from `s[:i]`, yielding `O(mn)` time and space. The key insight is that each row depends only on the previous row, so we can compress to a single array `dp[j]` representing the current row, updating it **backwards** (from `m-1` down to `0`) so that `dp[j]` still holds the "previous row" value when we need it to compute `dp[j+1]`. This reduces space to `O(m)` while keeping `O(mn)` time.

## Algorithm
1. Let `m = len(t)`. Create array `dp` of size `m+1` initialized to `0`. Set `dp[0] = 1` (empty `t` is a subsequence of any prefix of `s` in exactly one way).
2. For each character `ch` in `s`:
   - For `j` from `m-1` down to `0`:
     - If `ch == t[j]`, add `dp[j]` to `dp[j+1]`. This means: every way to form `t[:j]` from the previous prefix of `s` can be extended by matching this `ch` to `t[j]`, forming `t[:j+1]`.
3. After processing all of `s`, `dp[m]` holds the number of ways to form all of `t`. Return it.

## Line-by-Line Explanation
- `m = len(t)`: length of target string.
- `dp = [0] * (m + 1)`: 1D DP array; `dp[j]` = ways to form `t[:j]` from processed part of `s`.
- `dp[0] = 1`: base case — empty string is a subsequence exactly once.
- `for ch in s:`: iterate over source string characters.
- `for j in range(m - 1, -1, -1):`: iterate target indices **backwards** so that `dp[j]` (old row) is not overwritten before it's used to update `dp[j+1]`.
- `if ch == t[j]:`: current character of `s` matches `t[j]`.
- `dp[j + 1] += dp[j]`: extend all ways that formed `t[:j]` by using this match to form `t[:j+1]`.
- `return dp[m]`: final answer — ways to form entire `t`.

## Dry Run
Example: `s = "rabbbit"`, `t = "rabbit"` (`m=6`)

Initial `dp = [1,0,0,0,0,0,0]`

| Step | ch | j (loop) | Match? | dp before step | dp after step (changed indices) |
|------|----|----------|--------|----------------|---------------------------------|
| 1 | 'r' | 5..0 | j=0: 'r'=='r' | [1,0,0,0,0,0,0] | dp[1]+=dp[0] → [1,1,0,0,0,0,0] |
| 2 | 'a' | 5..0 | j=1: 'a'=='a' | [1,1,0,0,0,0,0] | dp[2]+=dp[1] → [1,1,1,0,0,0,0] |
| 3 | 'b' | 5..0 | j=2: 'b'=='b' | [1,1,1,0,0,0,0] | dp[3]+=dp[2] → [1,1,1,1,0,0,0] |
| 4 | 'b' | 5..0 | j=3: 'b'=='b', j=2: 'b'=='b' | [1,1,1,1,0,0,0] | j=3: dp[4]+=dp[3]=1 → [1,1,1,1,1,0,0]; j=2: dp[3]+=dp[2]=1 → [1,1,1,2,1,0,0] |
| 5 | 'b' | 5..0 | j=3: 'b'=='b', j=2: 'b'=='b' | [1,1,1,2,1,0,0] | j=3: dp[4]+=dp[3]=2 → [1,1,1,2,3,0,0]; j=2: dp[3]+=dp[2]=1 → [1,1,1,3,3,0,0] |
| 6 | 'i' | 5..0 | j=4: 'i'=='i' | [1,1,1,3,3,0,0] | dp[5]+=dp[4]=3 → [1,1,1,3,3,3,0] |
| 7 | 't' | 5..0 | j=5: 't'=='t' | [1,1,1,3,3,3,0] | dp[6]+=dp[5]=3 → [1,1,1,3,3,3,3] |

Return `dp[6] = 3`.

## Complexity
- **Time:** `O(n * m)` where `n = len(s)`, `m = len(t)`. The outer loop runs `n` times, the inner loop runs `m` times.
- **Space:** `O(m)` for the 1D `dp` array of size `m+1`.

## Edge Cases
- **`t` longer than `s`**: The inner loop never finds a match for the extra characters, `dp[m]` stays `0`. Correct.
- **All characters distinct, no match**: `dp[m]` remains `0`. Correct.
- **`s == t`**: Each character matches exactly once in forward order; `dp` builds up to `1`. Correct.
- **Repeated characters in `s` and `t`** (e.g., `s="aaa"`, `t="aa"`): Backwards iteration correctly accumulates combinations (`C(3,2)=3`). Verified by trace.
- **Maximum lengths (1000 each)**: `O(10^6)` operations, well within limits; `dp` array size 1001, trivial memory.

## Possible Improvements
The solution is already optimal in both time and space for the given constraints. The 1D backwards DP is the standard space-optimized form; further micro-optimizations (e.g., using `array('I')` or `list` comprehension) would not change asymptotic complexity and are unnecessary in Python for `n,m ≤ 1000`.
