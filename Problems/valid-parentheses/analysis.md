# 20. Valid Parentheses - Solution Analysis

## Problem Understanding
Given a string containing only the characters `()[]{}`, determine if every opening bracket has a matching closing bracket of the same type and brackets are properly nested. The string length is between 1 and 10⁴. Order matters: `([)]` is invalid because the closing `)` appears before the closing `]` despite `(` being opened before `[`.

## Approach
**Stack** – the canonical pattern for bracket matching. A stack naturally enforces LIFO ordering: the most recent unmatched opening bracket must be closed next. The brute-force approach would recursively remove adjacent matching pairs until none remain, costing O(n²) time. The stack reduces this to a single pass: push openings, pop and verify on closings. The key insight is that a closing bracket is valid *iff* it matches the top of the stack; any mismatch or empty stack means the string is invalid.

## Algorithm
1. Initialise an empty list `stack` and a dictionary `pairs` mapping each closing bracket to its corresponding opening bracket.
2. Iterate over each character `char` in the input string `s`.
3. If `char` is a closing bracket (i.e., a key in `pairs`):
   - If `stack` is empty **or** the top element (`stack.pop()`) does not equal `pairs[char]`, return `False`.
4. Otherwise (`char` is an opening bracket), append it to `stack`.
5. After the loop, return `True` if `stack` is empty (all openings matched), else `False`.

## Line-by-Line Explanation
- `stack = []`: holds unmatched opening brackets in order of appearance.
- `pairs = {')': '(', ']': '[', '}': '{'}`: constant-time lookup from closing to opening bracket.
- `for char in s:`: single left-to-right pass over the string.
- `if char in pairs:`: detects a closing bracket.
- `if not stack or stack.pop() != pairs[char]:`: two failure modes – no opening available, or the most recent opening doesn't match this closing.
- `return False`: immediate rejection on first mismatch.
- `else: stack.append(char)`: records an opening bracket for future matching.
- `return not stack`: valid only if every opening found its closing partner.

## Dry Run
Example: `s = "([)]"`

| Step | char | stack before | char in pairs? | pairs[char] | stack.pop() | Match? | Action |
|------|------|--------------|----------------|-------------|-------------|--------|--------|
| 1 | `(` | `[]` | No | – | – | – | push `(` → `['(']` |
| 2 | `[` | `['(']` | No | – | – | – | push `[` → `['(', '[']` |
| 3 | `)` | `['(', '[']` | Yes | `(` | `[` | No | return `False` |

The algorithm stops at step 3 because the top of stack (`[`) does not match the required opening for `)` (`(`).

## Complexity
- **Time:** O(n) – each character is processed once; dictionary lookup and stack operations are O(1).
- **Space:** O(n) – in the worst case (e.g., `(((((`) the stack holds all n characters. Here n = len(s) ≤ 10⁴.

## Edge Cases
- **Single bracket:** `"("` → stack non-empty at end → `False`.
- **All openings then all closings:** `"((()))"` → pushes three, pops three → `True`.
- **Mismatched types:** `"(]"` → closing `]` expects `[` but top is `(` → `False`.
- **Empty string:** not possible per constraints (length ≥ 1), but if allowed, `not stack` would correctly return `True`.
- **Maximum length (10⁴):** stack fits comfortably in memory; recursion depth not an issue.

## Possible Improvements
The solution is already optimal for the given constraints – O(n) time and O(n) space are the best achievable for this problem. A micro-optimisation would be to use a list as a stack (already done) and avoid the `in pairs` check by using a set of openings, but the current dictionary lookup is O(1) and perfectly readable. No material improvement exists.
