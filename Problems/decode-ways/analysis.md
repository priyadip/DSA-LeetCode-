# 91. Decode Ways - Solution Analysis

## Problem Understanding
Given a digit string `s` (length 1–100), count the number of ways to split it into valid codes 1–26 (mapping to A–Z). A code cannot have leading zeros (e.g., "06" is invalid). Return 0 if no valid decoding exists. The answer fits in a 32‑bit integer.

## Approach
**Dynamic Programming (bottom‑up, constant space).**  
The brute‑force recursion tries every partition, which is exponential. DP reduces this to linear time by observing that the number of decodings for a prefix depends only on the last one or two digits: a non‑zero last digit can stand alone (add ways from prefix without it), and a two‑digit suffix between "10" and "26" can be taken as a pair (add ways from prefix without those two). Keeping only the two previous counts yields O(1) space.

**Key insight:** `dp[i] = (s[i-1] != '0' ? dp[i-1] : 0) + (10 ≤ int(s[i-2:i]) ≤ 26 ? dp[i-2] : 0)`.

## Algorithm
1. Initialise `prev2 = 1` (ways to decode empty string) and `prev1 = 1` (acts as `dp[0]` for the first iteration).
2. For each prefix length `i` from 1 to `len(s)`:
   - `current = 0`.
   - If the last digit `s[i-1]` is not `'0'`, add `prev1` (single‑digit decode).
   - If `i ≥ 2` and the two‑digit substring `s[i-2:i]` is lexicographically between `"10"` and `"26"`, add `prev2` (two‑digit decode).
   - Shift: `prev2 = prev1`, `prev1 = current`.
3. Return `prev1` (holds `dp[n]` after the loop).

## Line-by-Line Explanation
- `prev2 = 1` – base case `dp[0] = 1` (empty string has one decoding).
- `prev1 = 1` – initialises `dp[0]` for the first iteration; will become `dp[1]` after `i=1`.
- `for i in range(1, len(s) + 1):` – iterate over prefix lengths 1…n.
- `current = 0` – accumulator for `dp[i]`.
- `if s[i - 1] != '0': current += prev1` – a non‑zero last digit can be a single letter; add ways for prefix of length `i-1`.
- `if i >= 2 and '10' <= s[i - 2:i] <= '26': current += prev2` – a valid two‑digit code (10–26) adds ways for prefix of length `i-2`.
- `prev2, prev1 = prev1, current` – slide the window: `prev2` becomes old `dp[i-1]`, `prev1` becomes new `dp[i]`.
- `return prev1` – after the loop, `prev1` holds `dp[n]`, the total decodings.

## Dry Run
Example `s = "226"` (expected 3).

| Step | i | s[i-1] | s[i-2:i] | prev2 | prev1 | current | Action |
|------|---|--------|----------|-------|-------|---------|--------|
| 1    | 1 | '2'    | –        | 1     | 1     | 1       | '2'!='0' → +prev1 |
| 2    | 2 | '2'    | "22"     | 1     | 1     | 2       | '2'!='0' → +prev1; "22" in 10..26 → +prev2 |
| 3    | 3 | '6'    | "26"     | 1     | 2     | 3       | '6'!='0' → +prev1; "26" in 10..26 → +prev2 |

Return `prev1 = 3`.

## Complexity
- **Time:** O(n) – one pass over the string, constant work per character.
- **Space:** O(1) – only three integer variables (`prev2`, `prev1`, `current`).

## Edge Cases
- **Leading zero** (`"06"`): first iteration yields `current=0`; subsequent iterations stay 0 → returns 0.
- **Single zero** (`"0"`): loop runs once, `current=0` → returns 0.
- **Valid two‑digit boundaries** (`"10"`, `"26"`): correctly counted via the two‑digit condition.
- **Two‑digit >26** (`"27"`): only single‑digit path taken → returns 1.
- **All zeros** (`"000"`): always 0.
- **Maximum length (100):** runs in O(100) time, well within limits.

## Possible Improvements
The solution is already optimal for the given constraints: O(n) time and O(1) space cannot be improved asymptotically. The string comparison `'10' <= s[i-2:i] <= '26'` is a clever constant‑time check that avoids integer conversion. Variable names are clear; no material redundancy exists.
