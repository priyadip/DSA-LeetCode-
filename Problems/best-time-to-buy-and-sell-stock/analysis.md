# 121. Best Time to Buy and Sell Stock - Solution Analysis

## Problem Understanding
Given an array `prices` where `prices[i]` is the stock price on day `i`, find the maximum profit achievable by buying on one day and selling on a strictly later day. If no profit is possible, return `0`. The constraints (`n ≤ 10^5`, `prices[i] ≤ 10^4`) require an O(n) or O(n log n) solution; an O(n²) brute-force check of all pairs is too slow.

## Approach
**Pattern:** Single-pass greedy / running minimum.  
**Why it fits:** The best buy day for any sell day is simply the minimum price seen before that day. By maintaining the running minimum and the best profit seen so far, we evaluate every possible sell day in O(1) amortised time.  
**Brute-force contrast:** Checking all (buy, sell) pairs costs O(n²) time. The chosen approach reduces this to O(n) by collapsing the buy-day search into a single variable.  
**Key insight:** For each day treated as a sell day, the optimal buy day is the minimum price among all previous days.

## Algorithm
1. Initialise `min_price = +∞` and `max_profit = 0`.
2. For each price `p` in `prices`:
   a. Update `max_profit = max(max_profit, p - min_price)` — profit if we sold today after buying at the lowest prior price.
   b. Update `min_price = min(min_price, p)` — incorporate today’s price into the running minimum for future days.
3. Return `max_profit`.

## Line-by-Line Explanation
- `min_s = float('inf')`: Initialises the running minimum price so that the first price becomes the new minimum.
- `max_p = 0`: Initialises maximum profit to 0, correctly handling the “no profit possible” case.
- `for p in prices:`: Iterates through each day’s price once.
- `max_p = max(max_p, p - min_s)`: Computes the profit from buying at the lowest price seen so far and selling today; keeps the larger of this profit and the previous best.
- `min_s = min(min_s, p)`: Updates the running minimum to include today’s price for subsequent iterations.
- `return max_p`: Returns the maximum profit found (0 if never positive).

## Dry Run
Example 1: `prices = [7,1,5,3,6,4]`

| Step | p | min_s | max_p | Action |
|------|---|-------|-------|--------|
| 1 | 7 | inf | 0 | max_p = max(0, 7-inf)=0; min_s = min(inf, 7)=7 |
| 2 | 1 | 7 | 0 | max_p = max(0, 1-7)=0; min_s = min(7, 1)=1 |
| 3 | 5 | 1 | 0 | max_p = max(0, 5-1)=4; min_s = min(1, 5)=1 |
| 4 | 3 | 1 | 4 | max_p = max(4, 3-1)=4; min_s = min(1, 3)=1 |
| 5 | 6 | 1 | 4 | max_p = max(4, 6-1)=5; min_s = min(1, 6)=1 |
| 6 | 4 | 1 | 5 | max_p = max(5, 4-1)=5; min_s = min(1, 4)=1 |
Result: 5.

## Complexity
- **Time:** O(n) — one pass through the `prices` array of length n; each iteration does O(1) work.
- **Space:** O(1) — only two scalar variables (`min_s`, `max_p`) are used, independent of n.

## Edge Cases
- **Single element** (`prices = [5]`): Loop runs once, `max_p` stays 0, returns 0 — correct because buy and sell must be on different days.
- **Strictly decreasing** (`[5,4,3,2,1]`): `max_p` never exceeds 0, returns 0 — correct.
- **All equal** (`[3,3,3]`): Profit always 0, returns 0 — correct.
- **Maximum size** (`n = 10^5`): O(n) time and O(1) space easily fit within limits.
- **Already sorted ascending** (`[1,2,3,4,5]`): Correctly yields 4 (buy at 1, sell at 5).

## Possible Improvements
The solution is already optimal for the given constraints — O(n) time and O(1) space cannot be improved asymptotically. A minor readability improvement would be renaming `min_s` → `min_price` and `max_p` → `max_profit`; the logic and performance are identical.
