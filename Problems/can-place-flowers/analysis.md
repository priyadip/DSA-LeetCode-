# 605. Can Place Flowers - Solution Analysis

## Problem Understanding
We are given a binary array `flowerbed` where `1` means a plot is occupied and `0` means empty. No two `1`s are adjacent in the input. We must determine whether we can plant `n` new flowers (turn `n` zeros into ones) such that no two flowers become adjacent. The array length is up to 2·10⁴, so an O(n) single pass is expected. Order matters only in the sense that we scan left-to-right; any valid placement works.

## Approach
The solution uses a **greedy** single-pass scan with **sentinel padding**. The brute-force would try all combinations of empty plots, which is exponential. The greedy insight: whenever three consecutive plots are empty (left, current, right), planting at the current plot is always safe and never harms future placements, because it only blocks the immediate neighbours which are already empty. Padding the array with a leading and trailing `0` eliminates special-case logic for the first and last positions.

## Algorithm
1. Prepend and append a `0` to `flowerbed` so boundary checks become uniform.
2. Iterate `i` from `1` to `len(flowerbed) - 2` (the original indices).
3. If `flowerbed[i-1]`, `flowerbed[i]`, and `flowerbed[i+1]` are all `0`:
   - Set `flowerbed[i] = 1` (plant a flower).
   - Decrement `n` if `n > 0`.
   - If `n` reaches `0`, return `True` immediately.
4. After the loop, return `True` iff `n == 0`.

## Line-by-Line Explanation
- `flowerbed = [0] + flowerbed + [0]`: Adds sentinel zeros at both ends so the first and last real plots have a "virtual" empty neighbour.
- `for i in range(1, len(flowerbed) - 1):`: Loops over the original array positions (now shifted by +1).
- `if flowerbed[i - 1] == 0 and flowerbed[i] == 0 and flowerbed[i + 1] == 0:`: Checks the greedy condition: current plot and both neighbours are empty.
- `flowerbed[i] = 1`: Plants a flower here, blocking neighbours for subsequent iterations.
- `if n > 0: n -= 1`: Decrements the remaining flowers to place only while we still need to place some.
- `if n == 0: return True`: Early exit once all required flowers are placed.
- `return n == 0`: After scanning, success only if no flowers remain to be placed.

## Dry Run
Example: `flowerbed = [1,0,0,0,1]`, `n = 1`

Padded: `[0, 1, 0, 0, 0, 1, 0]`

| Step | i | flowerbed[i-1] | flowerbed[i] | flowerbed[i+1] | Condition | Action |
|------|---|----------------|--------------|----------------|-----------|--------|
| 1 | 1 | 0 | 1 | 0 | False | skip |
| 2 | 2 | 1 | 0 | 0 | False | skip |
| 3 | 3 | 0 | 0 | 0 | True | plant at 3, n=0 → return True |

Output: `True`.

## Complexity
- Time: O(N), where N = len(flowerbed). One pass over the padded array.
- Space: O(N) for the new padded list (the original list is not modified in-place; a new list is created). Could be O(1) extra by handling boundaries explicitly.

## Edge Cases
- `n = 0`: Loop body never triggers early return; final `return n == 0` yields `True`. Correct.
- All zeros, e.g., `[0,0,0]`, `n = 2`: Padded `[0,0,0,0,0]`. Plants at i=1 (n=1), i=3 (n=0) → `True`. Maximum capacity formula `(len+1)//2` works.
- Single element `[0]`, `n = 1`: Padded `[0,0,0]`, i=1 qualifies → `True`.
- Single element `[1]`, `n = 1`: Padded `[0,1,0]`, i=1 fails → `False`.
- Already full valid bed, `n > 0`: No three consecutive zeros exist, loop finishes, returns `False`.

## Possible Improvements
- **Space**: Avoid allocating a new list by checking boundaries inline (`(i == 0 or flowerbed[i-1] == 0) and ...`). This reduces auxiliary space to O(1) without changing time complexity.
- **Variable name**: `n` is mutated; a local `remaining = n` would be clearer, though not required.
- The solution is already optimal in time (O(N)) for the given constraints. The O(N) space from padding is acceptable at 2·10⁴ but the O(1) space variant is a simple improvement.
