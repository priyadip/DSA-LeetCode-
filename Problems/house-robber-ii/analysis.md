# 213. House Robber II - Solution Analysis

## Problem Understanding
The input is a circular array of non-negative integers representing money in houses arranged in a circle, where the first and last houses are adjacent. We must select a subset of houses with no two adjacent (including the circular adjacency) to maximize the sum. The constraints (n ≤ 100, values ≤ 1000) allow an O(n) solution; the circular condition is the only complication over the linear House Robber problem.

## Approach
The algorithmic pattern is **Dynamic Programming** applied to two linear subproblems. The brute force would enumerate all 2ⁿ subsets, which is infeasible. The key insight: because house 0 and house n‑1 are adjacent, any valid solution must exclude at least one of them. Therefore the circular problem reduces to the maximum of two linear House Robber problems: one on houses 0…n‑2 (excluding the last) and one on houses 1…n‑1 (excluding the first). Each linear pass runs in O(n) time and O(1) space using the standard two‑variable DP.

## Algorithm
1. If the array has only one house, return its value.
2. Define a helper `rob_range(start, end)` that computes the maximum for the linear subarray `nums[start:end]` (end exclusive):
   - Initialize `prev2 = 0` (max up to i‑2) and `prev1 = 0` (max up to i‑1).
   - For each index `i` from `start` to `end‑1`:
     - Update `prev2, prev1 = prev1, max(prev1, prev2 + nums[i])`.
   - Return `prev1`.
3. Compute `case1 = rob_range(0, n‑1)` (exclude last house).
4. Compute `case2 = rob_range(1, n)` (exclude first house).
5. Return `max(case1, case2)`.

## Line-by-Line Explanation
- `n = len(nums)`: stores length for boundary checks and range endpoints.
- `if n == 1: return nums[0]`: handles the single-house case where circular adjacency is irrelevant.
- `def rob_range(start, end):`: helper that solves the linear House Robber problem on a slice.
- `prev2, prev1 = 0, 0`: DP state for “two houses back” and “previous house” maximums.
- `for i in range(start, end):`: iterates over the chosen subarray.
- `prev2, prev1 = prev1, max(prev1, prev2 + nums[i])`: updates DP – either skip current house (keep `prev1`) or rob it (add `nums[i]` to `prev2`).
- `return prev1`: after the loop, `prev1` holds the maximum for this subarray.
- `return max(rob_range(0, n - 1), rob_range(1, n))`: evaluates the two exclusive cases and returns the better.

## Dry Run
Example 2: `nums = [1,2,3,1]`, `n = 4`.

| 2    | 1 | 2       | 0     | 1     | max(1, 0+2)=2                         | prev2=1, prev1=2 |
| 3    | 2 | 3       | 1     | 2     | max(2, 1+3)=4                         | prev2=2, prev1=4 |
| End  |   |         |       |       | **return 4**                          |        |

| Step | i | nums[i] | prev2 | prev1 | new prev1 = max(prev1, prev2+nums[i]) | Action |
|------|---|---------|-------|-------|---------------------------------------|--------|

## Complexity
- **Time:** O(n) – two passes over at most n‑1 elements each, constant work per element.
- **Space:** O(1) – only a few integer variables (`prev2`, `prev1`, loop index) regardless of input size.

## Edge Cases
- **n = 1:** explicitly handled, returns the only house’s value.
- **n = 2:** `rob_range(0,1)` sees only first house, `rob_range(1,2)` sees only second; max correctly picks the larger.
- **All zeros:** both passes return 0, max is 0.
- **Large values (up to 1000) and n = 100:** sums fit easily in Python’s arbitrary-precision integers.
- The constraints guarantee `n ≥ 1`, so empty input is not a valid case.

## Possible Improvements
The solution is already optimal for the given constraints: O(n) time and O(1) space match the theoretical lower bounds. The helper function is clean and avoids code duplication. Inlining the helper would save a trivial function-call overhead but adds no asymptotic benefit. No further improvements are necessary.
