# 84. Largest Rectangle in Histogram - Solution Analysis

## Problem Understanding
Given an array `heights` where each element represents a bar of width 1, find the maximum rectangular area that fits entirely under the histogram. The rectangle's height is limited by the shortest bar in its span. Constraints: `n ≤ 10^5`, heights non-negative. An O(n²) brute force checking all spans is too slow; we need O(n) or O(n log n).

## Approach
**Monotonic Stack** (increasing heights). The stack stores pairs `(start_index, height)` where `start_index` is the leftmost position the bar at `height` can extend to. When a lower height `h` arrives, all taller bars on the stack can no longer extend rightward; we pop them, compute their maximal area using the current index as right boundary, and update `start` to the popped index so the new lower bar inherits the leftward reach. Appending a sentinel `0` flushes the stack at the end.  
**Key insight**: each bar's maximal rectangle is bounded on the left by the first lower bar and on the right by the first lower bar; the stack discovers the right boundary exactly when that lower bar appears.

## Algorithm
1. Append `0` to `heights` to act as a sentinel that forces all remaining bars to be popped.
2. Initialise empty `stack` and `max_area = 0`.
3. Iterate `i, h` over `heights`:
   - Set `start = i`.
   - While `stack` not empty and `stack[-1][1] > h`:
     - Pop `(index, height)`.
     - Update `max_area = max(max_area, height * (i - index))`.
     - Set `start = index` (the new bar can extend left to the popped bar's start).
   - Push `(start, h)` onto `stack`.
4. Return `max_area`.

## Line-by-Line Explanation
- `stack = []`: holds `(leftmost_index, height)` for bars in non-decreasing height order.
- `max_area = 0`: tracks the best area found.
- `heights.append(0)`: sentinel ensures every bar gets a right boundary.
- `for i, h in enumerate(heights):`: scan left to right.
- `start = i`: default left boundary for current bar.
- `while stack and stack[-1][1] > h:`: taller bars on stack cannot extend past `i`.
- `index, height = stack.pop()`: retrieve the bar that ends at `i-1`.
- `max_area = max(max_area, height * (i - index))`: width is `i - index` because `index` is the leftmost position that bar could reach.
- `start = index`: current bar `h` can extend left to the popped bar's start.
- `stack.append((start, h))`: push current bar with its effective left boundary.
- `return max_area`: final answer.

## Complexity
- **Time**: O(n) — each index is pushed once and popped at most once; the while loop total iterations ≤ n.
- **Space**: O(n) — stack holds at most n+1 pairs (including sentinel).

## Edge Cases
- **All equal heights** (e.g., `[5,5,5]`): stack grows to length n, sentinel pops all, area = 5*n computed correctly.
- **Strictly increasing** (e.g., `[1,2,3]`): no pops until sentinel; each bar's left boundary stays at its own index, areas computed on flush.
- **Strictly decreasing** (e.g., `[3,2,1]`): each new bar pops all previous; `start` collapses to 0, areas computed immediately.
- **Single bar** (`[5]`): sentinel triggers pop, area = 5*1 = 5.
- **Zero heights** (`[0,0,0]`): while condition `> h` never true (0 > 0 false), stack accumulates zeros; sentinel pops them, areas all zero.
- **Large n = 10^5**: O(n) time and space fit constraints.

## Possible Improvements
- The solution is already optimal in time and space for the given constraints.
- Minor readability: rename `start` to `left` or `leftmost` to clarify it represents the left boundary.
- The input list is mutated by `heights.append(0)`. If the caller must not see the mutation, copy first: `heights = heights + [0]` (O(n) extra space) or handle the flush after the loop without sentinel. Under typical LeetCode usage this is acceptable.
