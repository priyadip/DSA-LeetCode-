# 1929. Concatenation of Array - Solution Analysis

## Problem Understanding
Given an integer array `nums` of length `n` (1 ≤ n ≤ 1000), return a new array of length `2n` where the first `n` elements equal `nums` and the next `n` elements also equal `nums`. Order and duplicates must be preserved. The constraints are small enough that any linear approach works, but the problem expects the output array to be constructed explicitly.

## Approach
The solution uses **in-place array extension** (simulation via language built-in). The brute-force approach would allocate a new array of size `2n` and copy `nums` into both halves in a loop, costing O(n) time and O(n) extra space for the new array. The chosen approach leverages Python's `list.extend`, which appends all elements from an iterable to the list in amortized O(1) per element, modifying the original list. The key insight is that `extend` iterates over a snapshot of the original elements, so `nums.extend(nums)` safely doubles the list without an explicit loop or extra allocation.

## Algorithm
1. Call `nums.extend(nums)` to append every element of the current `nums` to the end of `nums`.
2. Return the mutated `nums`, which now has length `2n` and contains the concatenation.

## Line-by-Line Explanation
- `nums.extend(nums)`: Extends the list in place by iterating over the original elements of `nums` and appending each to the end, producing the concatenated sequence.
- `return nums`: Returns the same list object, now of length `2n`, satisfying the required output.

## Dry Run
Example: `nums = [1, 2, 1]`

| Step | nums before extend        | Action                     | nums after extend           |
|------|---------------------------|----------------------------|-----------------------------|
| 1    | [1, 2, 1]                 | extend with own elements   | [1, 2, 1, 1, 2, 1]          |

Return `[1, 2, 1, 1, 2, 1]`.

## Complexity
- Time: O(n), because `extend` visits each of the `n` original elements once and appends in amortized O(1).
- Space: O(1) auxiliary space (the mutation happens in place; the output array is the input array grown to size `2n`).

## Edge Cases
- Single element (`n = 1`): `nums = [5]` becomes `[5, 5]` — works because `extend` iterates over the single element.
- All elements equal: e.g., `[7, 7, 7]` → `[7, 7, 7, 7, 7, 7]` — no special handling needed.
- Maximum size (`n = 1000`): well within Python's list capacity; `extend` handles the resize internally.
- **Side effect**: the input list is mutated. If the caller retains a reference to the original list, they will see the concatenated version. Under LeetCode's isolated test harness this is acceptable, but in a library context it would be a breaking change.

## Possible Improvements
The solution is already optimal for the given constraints: O(n) time and O(1) extra space. If preserving the input is required, replace `nums.extend(nums)` with `return nums + nums` (creates a new list, O(n) extra space) or `ans = nums.copy(); ans.extend(nums); return ans` (explicit copy, same complexity). No further algorithmic improvement exists.
