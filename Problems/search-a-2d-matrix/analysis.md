# 74. Search a 2D Matrix - Solution Analysis

## Problem Understanding
The input is an m×n matrix where each row is sorted in non-decreasing order and the first element of each row is strictly greater than the last element of the previous row. This means the entire matrix, when read row by row, forms a single sorted 1D array. We must determine if a target integer exists in the matrix in O(log(m·n)) time. The constraints (m, n ≤ 100) are small, but the required logarithmic complexity rules out linear scans.

## Approach
The solution uses **binary search on a virtual flattened array**. Because the matrix rows are concatenated in sorted order, we can treat the 2D structure as a 1D sorted array of length m·n without actually flattening it (which would cost O(m·n) space and time). The key insight is that the 1D index `mid` maps to 2D coordinates via `row = mid // n` and `col = mid % n`. This reduces the problem to standard binary search on a sorted array, achieving O(log(m·n)) time and O(1) space.

## Algorithm
1. Compute `rows = len(matrix)` and `cols = len(matrix[0])`.
2. Initialise binary search bounds: `l = 0`, `r = rows * cols - 1`.
3. While `l <= r`:
   a. Compute `mid = l + (r - l) // 2`.
   b. Map `mid` to matrix indices: `ri = mid // cols`, `ci = mid % cols`.
   c. If `matrix[ri][ci] == target`, return `True`.
   d. If `matrix[ri][ci] < target`, set `l = mid + 1` (search right half).
   e. Else, set `r = mid - 1` (search left half).
4. Loop exits without finding target; return `False`.

## Line-by-Line Explanation
- `rows = len(matrix)`: number of rows m.
- `cols = len(matrix[0])`: number of columns n (matrix is non-empty per constraints).
- `l = 0`: left bound of virtual 1D array (first element).
- `r = rows * cols - 1`: right bound (last element).
- `while l <= r:`: standard binary search loop condition.
- `mid = l + (r - l) // 2`: midpoint avoiding overflow (not an issue in Python, but good habit).
- `ri = mid // cols`: row index of the virtual midpoint.
- `ci = mid % cols`: column index of the virtual midpoint.
- `if matrix[ri][ci] == target:`: found target at mapped position.
- `return True`: immediate success.
- `elif matrix[ri][ci] < target:`: target lies to the right in the virtual array.
- `l = mid + 1`: narrow search to upper half.
- `else:`: target lies to the left.
- `r = mid - 1`: narrow search to lower half.
- `return False`: exhausted search space without a match.

## Complexity
- Time: O(log(m·n)), because each iteration halves the search space of size m·n.
- Space: O(1), only a constant number of integer variables are used regardless of input size.

## Edge Cases
- Single element matrix (m=n=1): loop runs once, correctly returns True or False.
- Target smaller than all elements: `r` becomes -1, loop exits, returns False.
- Target larger than all elements: `l` becomes m·n, loop exits, returns False.
- Target equals first or last element: found on first or last iteration respectively.
- Matrix with one row (m=1) or one column (n=1): mapping formulas still hold (`mid // 1 = mid`, `mid % 1 = 0`).

## Possible Improvements
The solution is already optimal for the given constraints: it achieves the required O(log(m·n)) time and O(1) space. Variable names `l` and `r` are conventional but could be `left` and `right` for readability; `ri`/`ci` could be `row`/`col`. No algorithmic improvement is possible without changing the complexity class.
