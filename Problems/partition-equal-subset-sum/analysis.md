# 416. Partition Equal Subset Sum - Solution Analysis

## Problem Understanding
Given an array of positive integers, determine if it can be split into two subsets with equal sum. The total sum must be even; if odd, return false immediately. The problem reduces to finding a subset that sums to exactly half the total. Constraints (n ≤ 200, values ≤ 100) make a pseudo-polynomial DP feasible: maximum target is 10,000.

## Approach
**Pattern:** 0/1 Knapsack / Subset Sum with 1D Dynamic Programming.  
The brute force would try all 2^n subsets, which is infeasible for n=200. The DP approach builds reachable sums incrementally: for each number, update which sums can be formed by either taking or skipping it. The key insight is that we only need a boolean array of size `target+1` because each number can be used at most once, and iterating backwards prevents reusing the same number multiple times in one iteration.

## Algorithm
1. Compute `total = sum(nums)`. If `total` is odd, return `False`.
2. Set `target = total // 2`.
3. Initialise `dp` array of length `target+1` with `False`; set `dp[0] = True` (empty subset sums to 0).
4. For each `x` in `nums`:
   - Iterate `j` from `target` down to `x`:
     - `dp[j] = dp[j] or dp[j - x]` (sum `j` is reachable if it was already reachable or if `j-x` was reachable before this number).
5. Return `dp[target]`.

## Line-by-Line Explanation
- `total = sum(nums)`: total sum of all elements.
- `if total & 1: return False`: bitwise check for odd total; equal partition impossible.
- `target = total // 2`: the sum each subset must reach.
- `dp = [False] * (target + 1)`: boolean table where `dp[s]` means a subset summing to `s` exists using processed numbers.
- `dp[0] = True`: empty subset always achieves sum 0.
- `for x in nums:`: process each number once (0/1 choice).
- `for j in range(target, x - 1, -1):`: iterate backwards so each `x` contributes at most once per subset.
- `dp[j] = dp[j] or dp[j - x]`: update reachability; `dp[j-x]` reflects state before current `x` because of reverse iteration.
- `return dp[target]`: whether target sum is achievable.

## Dry Run
Example: `nums = [1,5,11,5]`, total=22, target=11.

| Step | x | j (loop) | dp before step (indices 0..11) | Action |
|------|---|----------|--------------------------------|--------|
| 1 | 1 | 11→1 | [T,F,F,F,F,F,F,F,F,F,F,F] | j=1: dp[1]=dp[1] or dp[0]=T |
| 2 | 5 | 11→5 | [T,T,F,F,F,F,F,F,F,F,F,F] | j=5: dp[5]=dp[5] or dp[0]=T; j=6: dp[6]=dp[6] or dp[1]=T |
| 3 | 11 | 11→11 | [T,T,F,F,F,T,T,F,F,F,F,F] | j=11: dp[11]=dp[11] or dp[0]=T |
| 4 | 5 | 11→5 | [T,T,F,F,F,T,T,F,F,F,F,T] | j=10: dp[10]=dp[10] or dp[5]=T; j=11: dp[11]=T or dp[6]=T (stays T) |

Final `dp[11]` is `True` → return `True`.

## Complexity
- Time: O(n * target) where n = len(nums) ≤ 200, target ≤ 10,000. Each of the n numbers scans at most target entries.
- Space: O(target) for the 1D `dp` array.

## Edge Cases
- **Odd total**: caught immediately by `total & 1`.
- **Single element**: n=1, total is that element; if even, target = element/2, but `x > target` so inner loop never runs, `dp[target]` stays `False` (correct, cannot split one element into two non-empty subsets with equal sum unless element=0, but constraints say nums[i] ≥ 1).
- **All elements equal**: e.g., `[2,2,2,2]` total=8 target=4; DP correctly finds subset `[2,2]`.
- **Large n, small values**: n=200, all 1s → total=200 target=100; DP runs 200*100 = 20,000 operations, well within limits.
- **No valid partition**: e.g., `[1,2,5]` total=8 target=4; DP ends with `dp[4]=False`.

## Possible Improvements
The solution is already optimal for the given constraints. Time O(n * target) and space O(target) are the best achievable for pseudo-polynomial subset sum. A minor readability improvement: rename `x` to `num` and `j` to `s` (sum) for clarity, but the logic is sound and no algorithmic gain exists.
