# 3702. Longest Subsequence With Non-Zero Bitwise XOR - Solution Analysis

## Problem Understanding
We are given an integer array `nums`. A subsequence is any subset of elements taken in their original order (order does not affect XOR). We need the maximum length of a subsequence whose bitwise XOR is non‑zero. If every possible subsequence has XOR zero (which happens only when all elements are zero), return 0. Constraints: `1 ≤ len(nums) ≤ 10^5`, `0 ≤ nums[i] ≤ 10^9`.

## Approach
The solution uses a **greedy / mathematical observation** pattern.  
Brute force would examine all subsets (exponential). The key insight is:  
*If the XOR of the entire array is non‑zero, the whole array is already the longest valid subsequence. If the total XOR is zero, removing any single non‑zero element makes the XOR equal to that element (non‑zero), yielding a subsequence of length `n‑1`. If all elements are zero, no non‑zero XOR subsequence exists.*

This reduces the problem to a single pass to compute the total XOR and a check for any non‑zero element.

## Algorithm
1. Compute `total_xor` as the XOR of all elements in `nums`.
2. If `total_xor != 0`, return `len(nums)` (the whole array works).
3. Otherwise, if there exists at least one non‑zero element in `nums`, return `len(nums) - 1` (remove one non‑zero element).
4. If all elements are zero, return `0`.

## Line-by-Line Explanation
- `x = 0` – initialise accumulator for the total XOR.
- `for num in nums: x ^= num` – compute XOR of the entire array in one pass.
- `if x != 0: return len(nums)` – total XOR is already non‑zero; the full array is a valid subsequence of maximum possible length.
- `if any(nums): return len(nums) - 1` – `any(nums)` is true iff at least one element is non‑zero. Removing that element changes the XOR from 0 to that non‑zero value, giving a valid subsequence of length `n‑1`.
- `return 0` – all elements are zero; every subsequence XOR is zero.

## Dry Run
Example: `nums = [1, 2, 3]`

| Step | num | x (after XOR) | Action |
|------|-----|---------------|--------|
| 1    | 1   | 1             |        |
| 2    | 2   | 3             |        |
| 3    | 3   | 0             | loop ends |
|      |     |               | `x == 0`, `any(nums)` true → return `3 - 1 = 2` |

Example: `nums = [2, 3, 4]` → total XOR = 5 ≠ 0 → return 3.  
Example: `nums = [0, 0, 0]` → total XOR = 0, `any(nums)` false → return 0.

## Complexity
- **Time:** O(n) – one pass to compute XOR, `any(nums)` is another pass but still linear; n = len(nums).
- **Space:** O(1) – only a few integer variables used.

## Edge Cases
- **All zeros:** correctly returns 0.
- **Single non‑zero element:** e.g., `[5]` → total XOR = 5 ≠ 0 → returns 1.
- **Single zero:** `[0]` → total XOR = 0, `any` false → returns 0.
- **Total XOR zero but contains non‑zero:** e.g., `[1, 2, 3]` → returns `n‑1`.
- **Large input (n = 10^5):** O(n) time and O(1) space easily fit constraints.

## Possible Improvements
The solution is already optimal in both time and space for the given constraints. A minor micro‑optimisation would be to combine the `any(nums)` check into the first loop (e.g., track a `has_non_zero` flag) to avoid a second pass, but this does not change the asymptotic complexity and the current code is clear and concise.
