# 1621. Number of Sets of K Non-Overlapping Line Segments - Solution Analysis

## Problem Understanding
We have `n` points at integer coordinates `0, 1, …, n-1`. We must choose exactly `k` non-overlapping line segments, each covering at least two points (so its endpoints are distinct integers). Segments may share endpoints but their interiors cannot overlap. The order of segments does not matter (it's a set). The answer is required modulo `10^9+7`. Constraints: `2 ≤ n ≤ 1000`, `1 ≤ k ≤ n-1`.

## Approach
The solution uses the combinatorial identity that the number of ways equals the binomial coefficient `C(n + k - 1, 2k)`. This identity arises from a stars-and-bars argument: each of the `k` segments contributes a start and an end point, and the non-overlapping condition with possible shared endpoints translates to choosing `2k` positions out of `n + k - 1` available "slots". The code computes this binomial coefficient modulo `10^9+7` using a 1D dynamic programming array that builds Pascal's triangle row by row. This is a standard method for moderate `n` (here `N = n+k-1 ≤ 1999`) and avoids precomputing factorials and modular inverses.

**Key insight:** The problem reduces to computing `C(n + k - 1, 2k)`.

## Algorithm
1. Set `MOD = 1_000_000_007`.
2. Let `r = 2 * k` and `N = n + k - 1`.
3. Initialise a 1D array `dp` of length `r+1` with `dp[0] = 1` (all other entries `0`). After processing `i` iterations, `dp[j]` will hold `C(i, j) mod MOD`.
4. For `i` from `1` to `N`:
   - For `j` from `min(i, r)` down to `1`:
       `dp[j] = (dp[j] + dp[j-1]) % MOD`  (Pascal's recurrence).
5. Return `dp[r]`.

## Line-by-Line Explanation
- `MOD = 10**9 + 7`: Modulus for all operations.
- `r = 2 * k`: We need the binomial coefficient `C(N, 2k)`.
- `N = n + k - 1`: The upper parameter of the binomial coefficient.
- `dp = [0] * (r + 1); dp[0] = 1`: `dp[j]` will eventually become `C(N, j)`. Initially it represents row `0` of Pascal's triangle.
- `for i in range(1, N + 1):`: Iterate over rows `1 … N` of Pascal's triangle.
- `for j in range(min(i, r), 0, -1):`: Update entries from right to left so that `dp[j-1]` still holds the value from the previous row.
- `dp[j] = (dp[j] + dp[j - 1]) % MOD`: Apply `C(i, j) = C(i-1, j) + C(i-1, j-1)`.
- `return dp[r]`: After the loop, `dp[r]` equals `C(N, r) mod MOD`.

## Complexity
- **Time:** `O(N * r) = O((n + k) * k)`. With `n, k ≤ 1000`, worst-case `N ≈ 2000`, `r ≈ 2000`, about 4 million operations.
- **Space:** `O(r) = O(k)` for the `dp` array.

## Edge Cases
- `k = 1`: `r = 2`, `N = n`. The code computes `C(n, 2)`, which is exactly the number of single segments.
- `n = 2, k = 1`: `N = 2, r = 2` → `C(2,2)=1`, the only segment `(0,1)`.
- Maximum constraints `n=1000, k=999`: `N=1998, r=1998`. The loops run within limits and the answer fits in the modulus.
- The formula holds for all allowed inputs; no special handling is needed.

## Possible Improvements
The solution is already optimal for the given constraints. The DP approach is simple, uses minimal space, and runs well within the time limit. An alternative using precomputed factorials and modular inverses would achieve `O(N)` precomputation and `O(1)` query, but with `N ≤ 2000` the current `O(N*k)` is perfectly adequate and avoids the extra code for modular inverses. No material improvement is necessary.
