# 1423. Maximum Points You Can Obtain from Cards - Solution Analysis

## Problem Understanding
We are given an array `cardPoints` representing points on cards in a row. We must take exactly `k` cards, each from either the start or the end of the array. The goal is to maximize the sum of the taken cards. Constraints: `n = len(cardPoints)` up to 10^5, values positive up to 10^4, `1 <= k <= n`. Since all values are positive, taking cards from the ends is equivalent to removing a contiguous subarray of length `n - k` from the middle; the score is total sum minus the sum of that removed subarray. We need the minimum possible sum of any subarray of length `n - k`.

## Approach
The solution uses the **sliding window** pattern (fixed-size window) to find the minimum sum subarray of length `window_size = n - k`. The brute-force approach would try all `O(n)` possible splits of taking `i` from left and `k-i` from right, each costing `O(k)` to sum, yielding `O(nk)` time. The sliding window reduces this to `O(n)` by maintaining the sum of the current window of size `n - k` and updating it in `O(1)` per step. The key insight: maximizing the sum of `k` cards taken from the ends is equivalent to minimizing the sum of the `n - k` cards left in the middle.

## Algorithm
1. Compute `n = len(cardPoints)` and `window_size = n - k`.
2. Compute the sum of the first `window_size` elements as the initial `window_sum` and set `min_window = window_sum`.
3. Slide the window one position right at a time for `i` from `window_size` to `n-1`:
   - Add `cardPoints[i]` to `window_sum` (new element entering).
   - Subtract `cardPoints[i - window_size]` from `window_sum` (old element leaving).
   - Update `min_window = min(min_window, window_sum)`.
4. Return `sum(cardPoints) - min_window`.

## Line-by-Line Explanation
- `n = len(cardPoints)`: store array length.
- `window_size = n - k`: length of the subarray we will *not* take (the middle segment).
- `window_sum = sum(cardPoints[:window_size])`: initial sum of the first window of size `window_size`.
- `min_window = window_sum`: initialize minimum window sum with the first window.
- `for i in range(window_size, n):`: iterate over each position where the window's right end moves.
- `window_sum += cardPoints[i]`: include the new rightmost element entering the window.
- `window_sum -= cardPoints[i - window_size]`: exclude the leftmost element leaving the window.
- `min_window = min(min_window, window_sum)`: track the smallest window sum seen.
- `return sum(cardPoints) - min_window`: total points minus the minimum middle segment gives the maximum score from the ends.

## Dry Run
Example: `cardPoints = [1,2,3,4,5,6,1]`, `k = 3`, `n = 7`, `window_size = 4`.

| Step | i | cardPoints[i] | cardPoints[i-4] | window_sum (before update) | window_sum (after update) | min_window | Action |
|------|---|---------------|-----------------|----------------------------|---------------------------|------------|--------|
| init | - | - | - | - | 1+2+3+4 = 10 | 10 | initial window [1,2,3,4] |
| 1 | 4 | 5 | 1 | 10 | 10+5-1 = 14 | 10 | window [2,3,4,5] |
| 2 | 5 | 6 | 2 | 14 | 14+6-2 = 18 | 10 | window [3,4,5,6] |
| 3 | 6 | 1 | 3 | 18 | 18+1-3 = 16 | 10 | window [4,5,6,1] |

Total sum = 22. `min_window = 10`. Result = 22 - 10 = 12. Matches expected output.

## Complexity
- Time: O(n), because we compute the initial window sum in O(window_size) ≤ O(n), then perform one pass of n - window_size = k iterations, each O(1). The final `sum(cardPoints)` is another O(n) pass, but combined it's still O(n).
- Space: O(1), only a few integer variables used regardless of input size.

## Edge Cases
- `k == n`: `window_size = 0`. The slice `cardPoints[:0]` is empty, `sum([])` is 0. The loop `range(0, n)` runs but `window_size` is 0, so `i - window_size == i`, and `window_sum += cardPoints[i]; window_sum -= cardPoints[i]` leaves `window_sum` at 0. `min_window` stays 0. Returns total sum - 0 = total sum. Correct (must take all cards).
- `k == 1`: `window_size = n - 1`. Initial window is all but last element. Loop runs once for `i = n-1`, window becomes all but first element. `min_window` is min of those two sums. Result is total - min = max(first, last). Correct.
- All elements equal: any window sum is same, min_window is that value, result is k * value. Correct.
- Large n up to 10^5: O(n) time and O(1) space fit easily.

## Possible Improvements
The solution is already optimal in time (O(n)) and space (O(1)) for the given constraints. A minor clarity improvement: compute `total = sum(cardPoints)` once before the loop and reuse it in the return statement, avoiding a second full pass over the array. This doesn't change asymptotic complexity but saves a constant factor.

```python
total = sum(cardPoints)
# ... sliding window ...
return total - min_window
```
