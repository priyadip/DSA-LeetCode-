# 2054. Two Best Non-Overlapping Events - Solution Analysis

## Problem Understanding
We are given a list of events, each with a start time, end time (inclusive), and a value. We may attend at most two events that do not overlap – meaning if one event ends at time `t`, the next must start at `t+1` or later. The goal is to maximize the sum of values of the chosen events. The constraints (up to 10⁵ events, times up to 10⁹) rule out O(n²) pair checking and require an O(n log n) or better solution.

## Approach
The solution uses **sorting + binary search + suffix maximum** (a form of dynamic programming / greedy preprocessing).  
Brute force would test all O(n²) pairs of events, which is too slow for n=10⁵.  
By sorting events by start time, any event that can follow a given event must have its start time strictly greater than the current event's end time. Because the array is sorted by start, all compatible second events form a contiguous suffix. The maximum value in that suffix can be precomputed in a `suffix_max` array, allowing O(1) lookup after a binary search finds the start of the suffix.  
**Key insight:** After sorting by start time, the best compatible second event for a given first event is simply the maximum value among all events that start after the first event's end.

## Algorithm
1. Sort `events` by start time ascending.
2. Extract `start_times` array from the sorted events.
3. Build `suffix_max` where `suffix_max[i]` = maximum value among events `i … n-1` (computed backwards).
4. Initialize `ans = 0`.
5. For each event `(start, end, value)` in the sorted list:
   - Use `bisect_right(start_times, end)` to find index `j` of the first event with start > `end`.
   - If `j < n`, update `ans = max(ans, value + suffix_max[j])`.
   - Update `ans = max(ans, value)` (attending only this event).
6. Return `ans`.

## Line-by-Line Explanation
- `events.sort()`: sorts events in-place by start time (then end, then value).
- `n = len(events)`: number of events.
- `start_times = [event[0] for event in events]`: array of start times for binary search.
- `suffix_max = [0] * n`: allocate suffix maximum array.
- `suffix_max[n - 1] = events[n - 1][2]`: base case – last event's value.
- `for i in range(n - 2, -1, -1): suffix_max[i] = max(suffix_max[i + 1], events[i][2])`: fill suffix max backwards.
- `ans = 0`: tracks best sum found.
- `for start, end, value in events:`: iterate each event as potential first event.
- `j = bisect_right(start_times, end)`: first index with start > `end` (non-overlapping condition).
- `if j < n: ans = max(ans, value + suffix_max[j])`: combine with best compatible second event.
- `ans = max(ans, value)`: consider taking only this event.
- `return ans`: final answer.

## Dry Run

## Complexity
- **Time:** O(n log n) – sorting O(n log n), building suffix_max O(n), n binary searches O(n log n).
- **Space:** O(n) – `start_times` and `suffix_max` arrays of length n.

## Edge Cases
- **All events overlap:** `bisect_right` returns `n` for every event, so only single-event values are considered; correct.
- **Multiple events with same start time:** sorting groups them; `suffix_max` correctly holds the maximum among them; binary search finds first start > end, which may skip the whole group if they all overlap.
- **Large values:** sum fits in Python int (unbounded); constraints guarantee ≤ 2·10⁶.
- **Minimum n = 2:** works without special handling.
- **Already sorted input:** still O(n log n) due to sort, but correct.
