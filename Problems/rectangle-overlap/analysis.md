# 836. Rectangle Overlap - Solution Analysis

## Problem Understanding
Given two axis-aligned rectangles defined by bottom-left and top-right coordinates, determine whether their intersection has positive area. Rectangles touching only at edges or corners do not count as overlapping. Input coordinates range from -10^9 to 10^9, and each rectangle is guaranteed to have non-zero area (x1 < x2, y1 < y2). The task is a pure geometric predicate with no ordering or duplicate concerns.

## Approach
The solution uses the **separating axis theorem** for axis-aligned rectangles: two rectangles overlap iff their projections overlap on both the x-axis and y-axis. The brute-force approach would compute the intersection rectangle explicitly and check its area, costing O(1) time but with more arithmetic. The chosen approach directly checks the negation — if one rectangle lies completely to the left/right or completely above/below the other, they cannot overlap. This reduces the problem to four simple comparisons. The key insight: **non-overlap on either axis implies no area overlap; overlap on both axes guarantees positive intersection area.**

## Algorithm
1. Unpack `rec1` into `x1, y1, x2, y2` and `rec2` into `a1, b1, a2, b2`.
2. Check horizontal separation: if `x2 <= a1` (rec1 right edge at or left of rec2 left edge) OR `a2 <= x1` (rec2 right edge at or left of rec1 left edge), return `False`.
3. Check vertical separation: if `y2 <= b1` (rec1 top edge at or below rec2 bottom edge) OR `b2 <= y1` (rec2 top edge at or below rec1 bottom edge), return `False`.
4. If neither separation condition holds, the projections overlap on both axes; return `True`.

## Line-by-Line Explanation
- `x1, y1, x2, y2 = rec1`: unpack first rectangle's corners.
- `a1, b1, a2, b2 = rec2`: unpack second rectangle's corners.
- `if x2 <= a1 or a2 <= x1:`: test whether rectangles are separated horizontally (one entirely left of the other). Using `<=` correctly treats edge-touching as non-overlap.
- `return False`: horizontal separation found, no overlap possible.
- `if y2 <= b1 or b2 <= y1:`: test whether rectangles are separated vertically (one entirely below the other).
- `return False`: vertical separation found, no overlap possible.
- `return True`: both projections overlap, so intersection area is positive.

## Complexity
- Time: O(1) — exactly four comparisons and a few assignments, independent of input magnitude.
- Space: O(1) — only a constant number of integer variables stored.

## Edge Cases
- **Edge-touching rectangles** (Example 2): correctly returns `False` because `<=` treats shared edges as separation.
- **Corner-touching rectangles** (Example 3): correctly returns `False` for the same reason.
- **One rectangle inside another**: both separation checks fail, returns `True` (positive intersection area).
- **Negative coordinates**: comparisons work identically; no special handling needed.
- **Maximum coordinate values (±10^9)**: Python integers handle this without overflow.
- **Degenerate rectangles**: constraints guarantee non-zero area, so `x1 < x2` and `y1 < y2` always hold; the code would still work if they didn't (would treat zero-area rectangles as non-overlapping with everything).
