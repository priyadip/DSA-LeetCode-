# 322. Coin Change - Solution Analysis

## Problem Understanding
We are given an array `coins` of distinct denominations (though duplicates would not break the logic) and a target `amount`. We have an infinite supply of each coin. The task is to find the minimum number of coins that sum exactly to `amount`, or return `-1` if impossible. The constraints (`amount ≤ 10⁴`, `coins.length ≤ 12`) make an O(amount × n) dynamic programming approach feasible, while brute-force combination search would be exponential.

## Approach
The solution uses **bottom-up dynamic programming** (the classic complete/unbounded knapsack pattern).  
Brute force would try all combinations of coins, which is exponential in `amount`.  
DP exploits optimal substructure: the minimum coins for amount `x` equals `1 + min(dp[x - coin])` over all usable coins.  
**Key insight:** Because each coin can be used repeatedly, we can build the answer for every value from `1` to `amount` by looking back at already computed smaller amounts.

## Algorithm
1. Create an array `dp` of length `amount + 1`, filled with `amount + 1` (a sentinel larger than any possible answer).
2. Set `dp[0] = 0` (zero coins needed to make amount 0).
3. For each `x` from `1` to `amount`:
   - For each `coin` in `coins`:
     - If `coin ≤ x`, update `dp[x] = min(dp[x], dp[x - coin] + 1)`.
4. After the loops, if `dp[amount]` still equals the sentinel, return `-1`; otherwise return `dp[amount]`.

## Line-by-Line Explanation
- `dp = [amount + 1] * (amount + 1)`: Initializes the DP table with a value that acts as infinity (any real answer ≤ amount).
- `dp[0] = 0`: Base case – zero coins make amount 0.
- `for x in range(1, amount + 1):`: Iterates over every target amount from 1 up to the desired amount.
- `for coin in coins:`: Tries each coin denomination.
- `if coin <= x:`: Only consider coins that do not exceed the current amount `x`.
- `dp[x] = min(dp[x], dp[x - coin] + 1)`: Relaxes the current best using the coin; `dp[x - coin]` is already optimal because we process amounts in increasing order.
- `return -1 if dp[amount] == amount + 1 else dp[amount]`: Returns the answer or `-1` if the sentinel was never replaced.

## Dry Run
Example: `coins = [1,2,5]`, `amount = 11`.

| x | coin=1 | coin=2 | coin=5 | dp[x] after inner loop |
|---|--------|--------|--------|------------------------|
| 1 | dp[0]+1=1 | skip | skip | 1 |
| 2 | dp[1]+1=2 | dp[0]+1=1 | skip | 1 |
| 3 | dp[2]+1=2 | dp[1]+1=2 | skip | 2 |
| 4 | dp[3]+1=3 | dp[2]+1=2 | skip | 2 |
| 5 | dp[4]+1=3 | dp[3]+1=3 | dp[0]+1=1 | 1 |
| 6 | dp[5]+1=2 | dp[4]+1=3 | dp[1]+1=2 | 2 |
| 7 | dp[6]+1=3 | dp[5]+1=2 | dp[2]+1=2 | 2 |
| 8 | dp[7]+1=3 | dp[6]+1=3 | dp[3]+1=3 | 3 |

Final `dp[11] = 3`, returned as answer.

## Complexity
- **Time:** O(amount × n), where `n = len(coins)`. The outer loop runs `amount` times, the inner loop at most `n` times (≤ 12). With `amount ≤ 10⁴`, this is well within limits.
- **Space:** O(amount) for the `dp` array of size `amount + 1`.

## Edge Cases
- `amount = 0`: The loop is skipped, `dp[0] = 0` is returned directly – correct.
- No combination possible (e.g., `coins = [2]`, `amount = 3`): `dp[3]` remains sentinel, returns `-1`.
- Coins larger than `amount`: The `if coin <= x` guard skips them, no effect.
- Duplicate denominations: The inner loop processes each duplicate, but `min` ensures correctness; slight redundant work only.
- Very large coin values (up to 2³¹−1): The guard `coin <= x` prevents index errors and unnecessary checks.

## Possible Improvements
The solution is already optimal for the given constraints.  
- Time complexity O(amount × n) is the best known for this problem (it is a classic unbounded knapsack).  
- Space is already O(amount); a 1D array is optimal.  
- Using `amount + 1` as sentinel avoids floating-point `inf` and is safe because the maximum possible coins is `amount` (using only 1-value coins).  
- Sorting `coins` and breaking early when `coin > x` would save a few iterations but does not change asymptotic complexity; the current code is clean and fast enough.
