# 1872. Stone Game VIII - Solution Analysis

## Problem Understanding
Alice and Bob alternately merge a prefix of length ≥2 from the left of the stone array, adding the prefix sum to their score and replacing the prefix with that sum. The game ends when one stone remains. The goal is to compute the final score difference (Alice − Bob) under optimal play. The array length is up to 10⁵, so an O(n) or O(n log n) solution is required; values can be negative, so greedy choices are not obvious.

## Approach
The solution uses **dynamic programming on prefix sums** with a **minimax** recurrence, optimized to O(1) space. The brute-force approach would explore all possible sequences of merges, which is exponential. The key insight is that the game state after any move is completely described by the suffix of the original array together with the sum of all merged stones as the new first element. This leads to a recurrence where the optimal score difference for the current player when the remaining stones start at index i is `dp[i] = max(dp[i+1], prefix[i] - dp[i+1])`, with `dp[n-1] = total sum`. The answer is `dp[1]` because the first move must take at least two stones (index ≥1).

## Algorithm
1. Compute prefix sums of `stones` in-place so that `stones[i]` becomes the sum of the first `i+1` stones.
2. Initialize `ans = stones[-1]` (the total sum), which represents `dp[n-1]`.
3. Iterate `i` from `n-2` down to `1`:
   - Update `ans = max(ans, stones[i] - ans)`. This computes `dp[i] = max(dp[i+1], prefix[i] - dp[i+1])` using the previous `ans` as `dp[i+1]`.
4. Return `ans`, which now holds `dp[1]`, the optimal score difference for Alice.

## Line-by-Line Explanation
- `n = len(stones)`: Stores the number of stones.
- `for i in range(1, n): stones[i] += stones[i - 1]`: Transforms `stones` into its prefix sums in-place; `stones[i]` now equals the sum of the first `i+1` original stones.
- `ans = stones[-1]`: Initializes `ans` with the total sum of all stones, which is the base case `dp[n-1]` (when only one stone remains, the current player takes it and the game ends).
- `for i in range(n - 2, 0, -1):`: Iterates backwards from the second-to-last prefix down to the prefix of length 2 (index 1), because the first move must remove at least two stones.
- `ans = max(ans, stones[i] - ans)`: Implements the recurrence `dp[i] = max(dp[i+1], prefix[i] - dp[i+1])`. `ans` before the update is `dp[i+1]`; `stones[i]` is `prefix[i]`. The new `ans` becomes `dp[i]`.
- `return ans`: Returns `dp[1]`, the maximum score difference Alice can guarantee.

## Dry Run

Trace of Example 1: `stones = [-1,2,-3,4,-5]`

**Prefix sum computation (in-place):**

| Step | i | stones[i] (before) | stones[i] (after) | Action |
|------|---|---------------------|-------------------|--------|
| 0 | 1 | 2 | 1 | stones[1] += stones[0] → 2 + (-1) = 1 |
| 1 | 2 | -3 | -2 | stones[2] += stones[1] → -3 + 1 = -2 |
| 2 | 3 | 4 | 2 | stones[3] += stones[2] → 4 + (-2) = 2 |
| 3 | 4 | -5 | -3 | stones[4] += stones[3] → -5 + 2 = -3 |

After prefix sums: `stones = [-1, 1, -2, 2, -3]`

**DP loop (i from n-2 down to 1):**

| Step | i | stones[i] | ans (before) | ans (after) | Action |
|------|---|-----------|--------------|-------------|--------|
| init | – | – | – | -3 | ans = stones[-1] = -3 |
| 1 | 3 | 2 | -3 | 5 | ans = max(-3, 2 - (-3)) = 5 |
| 2 | 2 | -2 | 5 | 5 | ans = max(5, -2 - 5) = 5 |
| 3 | 1 | 1 | 5 | 5 | ans = max(5, 1 - 5) = 5 |

Return `ans = 5`.

## Complexity

- **Time:** O(n), where n = len(stones). The prefix-sum loop runs n‑1 times and the DP loop runs n‑2 times; each iteration does O(1) work.
- **Space:** O(1) extra space. The input list is overwritten with prefix sums; only a few scalar variables are used.

## Edge Cases

- **n = 2 (minimum allowed):** The DP loop range `range(n-2, 0, -1)` becomes `range(0, 0, -1)` (empty). `ans` is set to the total sum, which is exactly the score difference when Alice must take both stones. Handled correctly.
- **All negative values:** The `max` operation works correctly with negative numbers (Example 1 and 3).
- **Large n (up to 10⁵):** O(n) time and O(1) extra space fit easily within limits.
- **Input modification:** The solution mutates `stones`. If the caller requires the original array unchanged, a separate prefix array would be needed (O(n) space), but LeetCode does not forbid in-place modification.
