# 334. Increasing Triplet Subsequence - Solution Analysis

## Problem Understanding
Given an integer array `nums`, determine whether there exist three indices `i < j < k` such that `nums[i] < nums[j] < nums[k]`. The array length can be up to 500,000, so an O(n²) or O(n log n) LIS approach is too slow; the follow-up explicitly asks for O(n) time and O(1) space. Values are 32-bit signed integers, and duplicates are allowed (strict inequality required).

## Approach
The solution uses a **greedy two-variable tracking** pattern. It maintains the smallest value seen so far (`first`) and the smallest value that has a smaller predecessor (`second`). This works because any value larger than `second` immediately forms a valid triplet with the values that established `first` and `second`. The brute-force would check all triples in O(n³) or use patience sorting for LIS in O(n log n); the greedy method achieves O(n) time and O(1) space by only remembering the two best candidates for the first two positions of a triplet. Key insight: we only need the smallest possible `first` and, given that, the smallest possible `second`; any later value exceeding `second` completes the triplet.

## Algorithm
1. Initialize `first = +∞` and `second = +∞`.
2. For each element `x` in `nums`:
   a. If `x ≤ first`, update `first = x` (new smallest candidate for the first position).
   b. Else if `x ≤ second`, update `second = x` (x is larger than `first` but smaller than current `second`, so it improves the second position).
   c. Else (`x > second`), return `True` (found a value larger than both `first` and `second`).
3. If the loop finishes, return `False`.

## Line-by-Line Explanation
- `first = float('inf')`: Tracks the minimum value seen so far; candidate for the first element of the triplet.
- `second = float('inf')`: Tracks the minimum value that has a smaller predecessor; candidate for the second element.
- `for x in nums:`: Iterates through each number once.
- `if x <= first:`: Current number can serve as a new, smaller first element.
- `first = x`: Updates the smallest seen value; this may discard a previous `first` but never invalidates a future triplet because a smaller `first` only makes it easier to find a valid `second` and third.
- `elif x <= second:`: `x` is larger than `first` (so it can be a second element) and improves (lowers) the current `second`.
- `second = x`: Records the best (smallest) second element seen so far that has a valid `first` before it.
- `else:`: `x` is strictly greater than both `first` and `second`; a valid triplet `(first, second, x)` exists.
- `return True`: Early exit on success.
- `return False`: No triplet found after scanning the entire array.

## Dry Run

| Step | x | first | second | Action |
|------|---|-------|--------|--------|
| 1 | 2 | inf | inf | 2 ≤ inf → first = 2 |
| 2 | 1 | 2 | inf | 1 ≤ 2 → first = 1 |
| 3 | 5 | 1 | inf | 5 > 1, 5 ≤ inf → second = 5 |
| 4 | 0 | 1 | 5 | 0 ≤ 1 → first = 0 |
| 5 | 4 | 0 | 5 | 4 > 0, 4 ≤ 5 → second = 4 |
| 6 | 6 | 0 | 4 | 6 > 0, 6 > 4 → return True |

At step 4, `first` becomes 0 (index 3) while `second` remains 5 (index 2). The algorithm still works because `second = 5` was set when `first = 1` (index 1 < index 2), proving a smaller value existed before 5. Updating `first` later does not invalidate that historical fact.

## Complexity
- Time: O(n), where n = len(nums). Single pass; each element triggers O(1) comparisons and assignments.
- Space: O(1). Only two scalar variables (`first`, `second`) are stored regardless of input size.

## Edge Cases
- **Length 1 or 2**: Loop never hits the `else` branch; returns `False` correctly.
- **All equal** (e.g., `[1,1,1]`): `x <= first` always true; `second` stays `inf`; returns `False`.
- **Strictly decreasing** (e.g., `[5,4,3,2,1]`): `first` updates each iteration; `second` never set; returns `False`.
- **Triplet uses non-consecutive indices** (e.g., `[5,1,5,0,4,6]`): `first` and `second` track the smallest valid candidates; the triplet `(1,4,6)` is detected at the final 6.
- **Negative numbers / large magnitude**: `float('inf')` dominates all `int` values per constraints; no overflow issues.
