# 2091. Removing Minimum and Maximum From Array - Solution Analysis

## Problem Understanding
We are given a 0-indexed array of distinct integers. We must remove both the minimum and maximum elements by repeatedly deleting either the first or last element of the array. The goal is to find the minimum number of such deletions required. The array length can be up to 10^5, so an O(n) solution is needed. Order matters because deletions are only allowed from the ends; the relative positions of the min and max determine the cost.

## Approach
The solution uses a **case analysis** (often categorized as greedy because we evaluate all feasible removal strategies and pick the best). Since we can only delete from the front or back, there are exactly three distinct ways to remove both target elements:
1. Delete from the front until both are gone.
2. Delete from the back until both are gone.
3. Delete from the front to remove one and from the back to remove the other.
We compute the cost of each scenario and return the minimum. The key insight is that the cost depends only on the indices of the minimum and maximum elements; the values of other elements are irrelevant.

## Algorithm
1. Scan the array once to find the indices `min_i` and `max_i` of the minimum and maximum values.
2. Let `a = min(min_i, max_i)` (the leftmost target) and `b = max(min_i, max_i)` (the rightmost target).
3. Compute three deletion counts:
   - **Front only**: `b + 1` (remove all elements up to and including the rightmost target).
   - **Back only**: `n - a` (remove all elements from the right up to and including the leftmost target).
   - **Both ends**: `a + 1 + n - b` (remove from front up to leftmost target, and from back up to rightmost target).
4. Return the minimum of these three values.

## Line-by-Line Explanation
- `n = len(nums)`: store array length.
- `min_i = max_i = 0`: initialize indices for min and max to the first element.
- `for i in range(n):`: iterate over all indices.
- `if nums[i] < nums[min_i]: min_i = i`: update min index when a smaller value is found.
- `if nums[i] > nums[max_i]: max_i = i`: update max index when a larger value is found.
- `if min_i < max_i: a = min_i; b = max_i else: b = min_i; a = max_i`: order the two indices so `a` is the leftmost and `b` the rightmost.
- `return min(b + 1, n - a, a + 1 + n - b)`: evaluate the three scenarios and return the smallest.

## Dry Run
Example 1: `nums = [2,10,7,5,4,1,8,6]`, `n = 8`.

| Step | i | nums[i] | min_i | max_i | Action |
|------|---|---------|-------|-------|--------|
| 0 | 0 | 2 | 0 | 0 | initial |
| 1 | 1 | 10 | 0 | 1 | 10 > 2 → max_i=1 |
| 2 | 2 | 7 | 0 | 1 | no change |
| 3 | 3 | 5 | 0 | 1 | no change |
| 4 | 4 | 4 | 0 | 1 | no change |
| 5 | 5 | 1 | 5 | 1 | 1 < 2 → min_i=5 |
| 6 | 6 | 8 | 5 | 1 | no change |
| 7 | 7 | 6 | 5 | 1 | no change |

After loop: `min_i=5`, `max_i=1`. Since `min_i > max_i`, `a = max_i = 1`, `b = min_i = 5`.
Options:
- `b + 1 = 6`
- `n - a = 8 - 1 = 7`
- `a + 1 + n - b = 1 + 1 + 8 - 5 = 5`
Minimum is `5`, matches expected output.

## Complexity
- Time: O(n), because we scan the array once to find min and max indices.
- Space: O(1), only a few integer variables are used regardless of input size.

## Edge Cases
- **Single element** (`n = 1`): `min_i = max_i = 0`, `a = b = 0`. All three options evaluate to 1, correctly returning 1.
- **Min and max at opposite ends** (e.g., `[1, ..., 100]`): `a = 0`, `b = n-1`. Options: `n`, `n`, `1 + 1 = 2` → correctly picks 2 (remove both ends).
- **Min and max adjacent** (e.g., `[..., 5, 10, ...]`): the both-ends option often wins.
- **Already sorted ascending/descending**: handled naturally by index ordering.
- **Negative numbers**: comparison works because distinct integers include negatives.

All cases are covered by the constraints (distinct, length ≥ 1).

## Possible Improvements
The solution is already optimal in time (O(n)) and space (O(1)) for the given constraints. A minor readability improvement would be to rename `a` and `b` to `left` and `right` (or `first` and `last`) to make the meaning clearer, but this does not affect performance. No algorithmic improvement is possible because any solution must at least locate the min and max, which requires Ω(n) time.
