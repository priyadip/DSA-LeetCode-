# 643. Maximum Average Subarray I - Solution Analysis

## Problem Understanding
Given an integer array `nums` of length `n` and an integer `k` (1 ≤ k ≤ n ≤ 10⁵), find the maximum average of any contiguous subarray of length exactly `k`. The array elements range from -10⁴ to 10⁴. Since `k` is fixed, maximizing the average is equivalent to maximizing the sum of the window. The answer must be accurate within 10⁻⁵.

## Approach
**Sliding Window** (fixed-size). The brute-force approach would compute the sum of every length-`k` subarray independently, costing O(n·k) time. Because consecutive windows overlap by `k-1` elements, we can maintain the current window sum in O(1) per step: subtract the element exiting the window and add the new element entering. This reduces the total time to O(n) with O(1) extra space. The key insight is that for a fixed window size, the maximum average corresponds exactly to the maximum sum, so we only need to track the maximum window sum.

## Algorithm
1. Compute the sum of the first `k` elements; store it as both the current window sum `sl` and the best sum `ans`.
2. Iterate `i` from `k` to `n-1` (the index of the new element entering the window):
   - Update `sl` by subtracting `nums[i-k]` (the element leaving) and adding `nums[i]` (the element entering).
   - If `sl > ans`, update `ans = sl`.
3. After the loop, return `ans / k` as a float.

## Line-by-Line Explanation
- `ans = sl = sum(nums[:k])`: Initialise both the best sum and the current window sum with the sum of the first `k` elements.
- `for i in range(k, len(nums)):`: Slide the window rightwards; `i` is the index of the new element entering.
- `sl += - nums[i-k] + nums[i]`: Remove the leftmost element of the previous window (`nums[i-k]`) and add the new rightmost element (`nums[i]`).
- `if sl > ans:`: Check whether the new window sum improves the maximum.
- `ans = sl`: Record the new maximum sum.
- `return ans / k`: Convert the maximum sum to the maximum average.

## Dry Run
Example: `nums = [1,12,-5,-6,50,3]`, `k = 4`

| Step | i | nums[i] | nums[i-k] | sl (before) | sl (after) | ans | Action |
|------|---|---------|-----------|-------------|------------|-----|--------|
| init | - | - | - | - | 2 | 2 | sum([1,12,-5,-6]) = 2 |
| 1 | 4 | 50 | 1 | 2 | 51 | 51 | sl = 2 - 1 + 50 = 51; ans updated |
| 2 | 5 | 3 | 12 | 51 | 42 | 51 | sl = 51 - 12 + 3 = 42; ans unchanged |

Return `51 / 4 = 12.75`.

## Complexity
- Time: O(n), because we compute the initial sum in O(k) and then perform one O(1) update per remaining element (n - k steps). Since k ≤ n, total is O(n).
- Space: O(1), only a few scalar variables are used regardless of input size.

## Edge Cases
- `k == n`: The loop body never executes; `ans` remains the sum of the entire array, and the average is returned correctly.
- `k == 1`: The window size is 1; the algorithm correctly finds the maximum element (since average = element).
- All negative numbers: The initial sum and updates handle negatives naturally; the maximum (least negative) sum is tracked.
- Large `n` (10⁵): The O(n) time and O(1) space fit comfortably within limits.

## Possible Improvements
The solution is already optimal in both time (O(n)) and space (O(1)) for the given constraints. A minor readability improvement would be to write the window update as `sl += nums[i] - nums[i-k]` instead of `sl += - nums[i-k] + nums[i]`, but this is purely stylistic and does not affect performance.
