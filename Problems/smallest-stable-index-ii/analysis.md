# 3904. Smallest Stable Index II - Solution Analysis

## Problem Understanding
We need the smallest index `i` such that `max(nums[0..i]) - min(nums[i..n-1]) ≤ k`. The array length `n` is up to 10⁵, so an O(n²) brute force (recomputing max/min for each `i`) is too slow. The values are non‑negative, but the logic works for any integers. Order matters because we must return the *first* stable index.

## Approach
The solution uses **prefix/suffix precomputation** (a form of dynamic programming on arrays).  
Brute force would compute the prefix maximum and suffix minimum for every index independently, costing O(n²). By precomputing `prefix_max[i] = max(nums[0..i])` in one forward pass and `suffix_min[i] = min(nums[i..n-1])` in one backward pass, we reduce the work to O(n) time and O(n) space.  
**Key insight:** The instability score at index `i` is exactly `prefix_max[i] - suffix_min[i]`; once both arrays are known, a single linear scan finds the answer.

## Algorithm
1. Build `prefix_max` where `prefix_max[i]` is the maximum of `nums[0..i]`.
2. Build `suffix_min` where `suffix_min[i]` is the minimum of `nums[i..n-1]`.
3. For `i` from `0` to `n-1`:
   - If `prefix_max[i] - suffix_min[i] ≤ k`, return `i`.
4. Return `-1` if no index satisfies the condition.

## Line-by-Line Explanation
- `n = len(nums)`: stores the length (unused later, harmless).
- `prefix_max = list(accumulate(nums, max))`: `itertools.accumulate` with `max` yields the running maximum, i.e. the prefix maxima.
- `suffix_min = list(accumulate(nums[::-1], min))[::-1]`: reverses `nums`, computes running minima (which correspond to suffix minima in the original order), then reverses back to align indices.
- `for i in range(len(nums)):`: iterates over every index from left to right.
- `if prefix_max[i] - suffix_min[i] <= k:`: checks the instability score against `k`.
- `return i`: returns the first (smallest) stable index found.
- `return -1`: executed if the loop finishes without finding a stable index.

## Dry Run
Example: `nums = [5,0,1,4]`, `k = 3`.

| Step | i | nums[i] | prefix_max | suffix_min | prefix_max[i] - suffix_min[i] | Action |
|------|---|---------|------------|------------|-------------------------------|--------|
| 1    | 0 | 5       | 5          | 0          | 5                             | continue |
| 2    | 1 | 0       | 5          | 0          | 5                             | continue |
| 3    | 2 | 1       | 5          | 1          | 4                             | continue |
| 4    | 3 | 4       | 5          | 4          | 1 ≤ 3                         | return 3 |

`prefix_max = [5,5,5,5]` (running max).  
`suffix_min` computed via reverse: `nums[::-1] = [4,1,0,5]` → accumulate min → `[4,1,0,0]` → reverse → `[0,0,1,4]`.

## Complexity
- **Time:** O(n). `accumulate` makes one pass each for prefix and suffix; the final loop is one more pass. All operations inside are O(1).
- **Space:** O(n). Two auxiliary arrays of length `n` are stored.

## Edge Cases
- **Single element** (`n = 1`): `prefix_max[0] = suffix_min[0] = nums[0]`, difference 0 ≤ k (since k ≥ 0) → returns 0. Correct.
- **All elements equal**: difference always 0 → returns 0 if k ≥ 0.
- **No stable index** (Example 2): loop completes, returns -1.
- **Large n (10⁵)**: O(n) time and space fit comfortably within limits.
- **k = 0**: requires exact equality of prefix max and suffix min; handled naturally.
- **Already sorted ascending**: prefix max = nums[i], suffix min = nums[i] → difference 0 → returns 0.
- **Already sorted descending**: prefix max = nums[0], suffix min = nums[n-1] → difference may exceed k; algorithm still works.

## Possible Improvements
The solution is already optimal in **time complexity** (O(n) is the best possible because every element must be examined).  
**Space** can be reduced from two arrays to one: compute `suffix_min` first (O(n) space), then scan left‑to‑right while maintaining a running `prefix_max` variable, eliminating the `prefix_max` array. This halves the auxiliary space (still O(n) due to `suffix_min`). The current code also stores an unused `n` variable. These are minor; the solution is clean and acceptable for the given constraints.
