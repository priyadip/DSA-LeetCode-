# 3718. Smallest Missing Multiple of K - Solution Analysis

## Problem Understanding
Given an array `nums` and integer `k`, find the smallest positive multiple of `k` that does not appear in `nums`. Constraints are small (`nums.length ≤ 100`, values ≤ 100), so a direct simulation with a hash set for O(1) lookups is sufficient. Order and duplicates in `nums` are irrelevant; only membership matters.

## Approach
**Hash Set + Linear Search on Multiples**. The brute force would be to check each multiple of `k` against the array with linear scans, costing O(m·n) where m is the number of multiples checked. By inserting all `nums` into a hash set first, each membership test becomes O(1), reducing the search to O(m) time. The key insight: the answer is the first multiple `k, 2k, 3k, …` absent from the set, and because values are bounded (≤ 100), the loop terminates quickly.

## Algorithm
1. Insert all elements of `nums` into a hash set `s`.
2. Initialise `x = k` (the first positive multiple).
3. While `x` is present in `s`, increment `x` by `k` (move to the next multiple).
4. Return `x` — the first multiple not found in the set.

## Line-by-Line Explanation
- `s = set(nums)`: Build a hash set for O(1) containment checks.
- `x = k`: Start with the smallest positive multiple of `k`.
- `while x in s:`: Repeatedly test whether the current multiple exists in the input.
- `x += k`: Advance to the next multiple of `k`.
- `return x`: The loop exits exactly when `x` is missing; this is the answer.

## Dry Run
Example 1: `nums = [8,2,3,4,6]`, `k = 2`

| Step | x | x in s? | Action |
|------|---|---------|--------|
| 1 | 2 | True | x = 4 |
| 2 | 4 | True | x = 6 |
| 3 | 6 | True | x = 8 |
| 4 | 8 | True | x = 10 |
| 5 | 10 | False | return 10 |

Example 2: `nums = [1,4,7,10,15]`, `k = 5`

| Step | x | x in s? | Action |
|------|---|---------|--------|
| 1 | 5 | False | return 5 |

## Complexity
- Time: O(n + m), where n = len(nums) (building the set) and m = answer/k (number of multiples checked). With constraints ≤ 100, m ≤ 101, so effectively O(n).
- Space: O(n) for the hash set storing up to 100 integers.

## Edge Cases
- **Answer is k itself**: Handled — loop body never executes, returns `k` (Example 2).
- **All multiples up to max(nums) present**: Loop continues past max(nums) and returns the next multiple (Example 1).
- **Duplicates in nums**: Set deduplicates automatically; no effect on correctness.
- **Single-element array**: Works identically.
- **k = 1**: Returns the smallest positive integer missing from `nums` (classic "first missing positive" on a bounded domain).

## Possible Improvements
The solution is already optimal for the given constraints. Time and space are both linear in the input size, and the constant factors are minimal. No algorithmic improvement is possible (must read all input). A micro-optimisation would be to compute `max(nums)` and start from `k * (max(nums)//k + 1)` if `max(nums) % k == 0`, but the current loop is simpler and fast enough for n ≤ 100.
