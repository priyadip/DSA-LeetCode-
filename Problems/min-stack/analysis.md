# 155. Min Stack - Solution Analysis

## Problem Understanding
Design a stack supporting push, pop, top, and getMin operations, all in O(1) time. The stack stores 32-bit signed integers; pop, top, and getMin are guaranteed to be called only on non-empty stacks. Up to 30,000 total operations will be performed.

## Approach
The solution uses the **two-stack (auxiliary stack)** pattern. A secondary stack tracks the minimum value at each depth of the primary stack. This suits the problem because getMin must be O(1); scanning the stack on each call would be O(n). The auxiliary stack adds O(n) space but guarantees O(1) for every operation. Key insight: storing the running minimum alongside each element lets us retrieve and update the minimum in constant time on both push and pop.

## Algorithm
1. Initialize two empty lists: `stack` for values, `min_stack` for minimums.
2. **push(value)**: Append `value` to `stack`. If `min_stack` is empty, append `value`; otherwise append `min(value, min_stack[-1])`.
3. **pop()**: Remove the last element from both `stack` and `min_stack`.
4. **top()**: Return `stack[-1]`.
5. **getMin()**: Return `min_stack[-1]`.

## Line-by-Line Explanation
- `self.stack = []`: Primary stack holding all pushed values.
- `self.min_stack = []`: Auxiliary stack where each entry is the minimum of all elements up to that depth.
- `self.stack.append(value)`: Records the new element in the main stack.
- `if not self.min_stack: self.min_stack.append(value)`: First element becomes the initial minimum.
- `else: self.min_stack.append(min(value, self.min_stack[-1]))`: New minimum is the smaller of the incoming value and the previous minimum.
- `self.stack.pop()`: Removes the top value from the main stack.
- `self.min_stack.pop()`: Removes the corresponding minimum, restoring the previous minimum.
- `return self.stack[-1]`: Returns the top element without mutation.
- `return self.min_stack[-1]`: Returns the current minimum in O(1) time.

## Complexity
- Time: O(1) for `push`, `pop`, `top`, `getMin` — each performs a constant number of list operations (append, pop, index access).
- Space: O(n) where n is the number of elements currently in the stack — both `stack` and `min_stack` store one entry per pushed element.

## Edge Cases
- **Single element**: `push(5); getMin() → 5; pop(); push(10); getMin() → 10` works because `min_stack` is rebuilt from empty on each new first push.
- **All equal values**: `push(2); push(2); push(2)` → `min_stack` becomes `[2, 2, 2]`; `pop` correctly maintains the minimum.
- **Strictly decreasing sequence**: `push(5); push(4); push(3)` → `min_stack` tracks each new minimum `[5, 4, 3]`; `getMin` returns the latest.
- **Strictly increasing sequence**: `push(1); push(2); push(3)` → `min_stack` stays `[1, 1, 1]`; `pop` does not affect the minimum until the last `1` is removed.
- **Negative values and zero**: Handled naturally by `min`; constraints guarantee `val` fits in 32-bit signed integer, so no overflow in Python.
- **Maximum operations (3·10⁴)**: Both lists grow to at most that size; list append/pop are amortized O(1) in CPython, so the solution stays within limits.

## Possible Improvements
The solution is already optimal for the given constraints — O(1) time per operation and O(n) space is the theoretical lower bound for this problem. A minor space optimization would be to store tuples `(value, current_min)` in a single list, halving the number of list objects, but the asymptotic complexity remains identical and the two-list approach is clearer. No further algorithmic improvement is possible.
