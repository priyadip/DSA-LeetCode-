# 746. Min Cost Climbing Stairs - Solution Analysis

## Problem Understanding
Given an array `cost` where `cost[i]` is the cost to step on the i-th stair, find the minimum total cost to reach the top (position `n`, just past the last index). You may start at index 0 or 1 without paying their cost upfront; thereafter, each move of 1 or 2 steps requires paying the cost of the step you land on. The constraints (n ≤ 1000, costs ≤ 999) allow an O(n) time and O(n) space solution; O(1) space is also achievable.

## Approach
**Dynamic Programming (bottom-up tabulation)**. The problem has optimal substructure: the minimum cost to reach step `i` depends only on the minimum costs to reach steps `i-1` and `i-2`. A brute-force recursion would explore 2^n paths; DP computes each subproblem once in order. The key insight is that `dp[i]` (minimum cost to reach step `i`) equals `min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])`, with `dp[0] = dp[1] = 0` because starting at step 0 or 1 incurs no initial cost.

## Algorithm
1. Let `n = len(cost)`. Create an array `dp` of size `n+1` initialized to 0. `dp[i]` will hold the minimum cost to reach step `i` (where step `n` is the top).
2. For `i` from 2 to `n` inclusive:
   - Compute `dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])`.
3. Return `dp[n]`.

## Line-by-Line Explanation
- `n = len(cost)`: number of stairs; the top is at index `n`.
- `dp = [0]*(n+1)`: allocate DP table; `dp[0]` and `dp[1]` are 0 (starting positions cost nothing).
- `for i in range(2, n+1):`: iterate over each reachable step from 2 up to the top.
- `dp[i] = min((dp[i-1] + cost[i-1]) , (dp[i-2] + cost[i-2]))`: to reach step `i`, either come from `i-1` (pay `cost[i-1]`) or from `i-2` (pay `cost[i-2]`); take the cheaper total.
- `return dp[n]`: minimum cost to reach the top.

## Dry Run
Example 1: `cost = [10, 15, 20]`, `n = 3`.

| Step | i | cost[i-1] | cost[i-2] | dp[i-1] | dp[i-2] | dp[i] calculation | dp[i] |
|------|---|-----------|-----------|---------|---------|-------------------|-------|
| init |   |           |           | 0       | 0       |                   | dp=[0,0,0,0] |
| 1    | 2 | 15        | 10        | 0       | 0       | min(0+15, 0+10)   | 10    |
| 2    | 3 | 20        | 15        | 10      | 0       | min(10+20, 0+15)  | 15    |

Return `dp[3] = 15`. Matches expected output.

## Complexity
- **Time**: O(n) — single loop from 2 to n, constant work per iteration.
- **Space**: O(n) — `dp` array of size n+1. (Can be reduced to O(1) by keeping only the last two values.)

## Edge Cases
- **Minimum length (n=2)**: loop runs once for `i=2`; `dp[2] = min(cost[1], cost[0])`, correct.
- **All zero costs**: `dp` stays zero, returns 0 — correct.
- **Large costs (up to 999)**: sums fit easily in Python int; no overflow concerns.
- **Multiple optimal paths**: `min` picks one; any optimal cost is fine.

## Possible Improvements
- **Space optimization**: replace `dp` array with two variables (`prev2`, `prev1`) updated each iteration, reducing space to O(1) without changing time complexity.
- The current solution is already optimal in time for the given constraints; the space improvement is minor but straightforward.
