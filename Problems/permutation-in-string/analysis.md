# 567. Permutation in String - Solution Analysis

## Problem Understanding
Given two strings `s1` and `s2`, determine whether any permutation of `s1` appears as a contiguous substring in `s2`. Both strings contain only lowercase English letters, with lengths up to 10⁴. A permutation means identical character frequencies; order does not matter. The task is a decision problem returning a boolean.

## Approach
The solution uses a **fixed-size sliding window** with **frequency counters** (hash maps). The window size equals `len(s1)`. We maintain a frequency map of the current window in `s2` and compare it against the frequency map of `s1`. If they match at any position, a permutation exists.

Brute force would generate all permutations of `s1` (O(k!) where k = len(s1)) or check every substring of length k in `s2` by sorting (O(n·k log k)). The sliding window reduces this to O(n) by updating the frequency map in O(1) per step: add the new right character, remove the leftmost character, and compare maps.

Key insight: two strings are permutations of each other iff their character frequency maps are identical. Since the alphabet is fixed (26 lowercase letters), map comparison is O(1).

## Algorithm
1. Build `target` frequency map from `s1`.
2. Build initial `window` frequency map from the first `len(s1)` characters of `s2`.
3. If `window == target`, return `True`.
4. Slide the window one position right for each `right` from `len(s1)` to `len(s2)-1`:
   a. Increment count of `s2[right]` in `window`.
   b. Identify `left_char = s2[right - len(s1)]` (character leaving the window).
   c. Decrement count of `left_char` in `window`.
   d. If count reaches zero, delete the key to keep maps comparable.
   e. If `window == target`, return `True`.
5. After loop, return `False`.

## Line-by-Line Explanation
- `target = Counter(s1)`: frequency map of `s1`; the pattern we search for.
- `window = Counter(s2[:len(s1)])`: frequency map of the first window in `s2`.
- `if window == target: return True`: check initial window before sliding.
- `for right in range(len(s1), len(s2)):`: iterate over each new character entering the window.
- `window[s2[right]] += 1`: add the new rightmost character to the window.
- `left_char = s2[right - len(s1)]`: character that exits the window on the left.
- `window[left_char] -= 1`: remove its contribution.
- `if window[left_char] == 0: del window[left_char]`: prune zero-count keys so `Counter` equality works correctly (missing key ≠ zero count).
- `if window == target: return True`: compare maps after each slide.
- `return False`: no matching window found.

## Complexity
- Time: O(n) where n = len(s2). Each character enters and leaves the window once; Counter equality checks at most 26 keys (constant).
- Space: O(1) — both Counters hold at most 26 entries (lowercase English letters), independent of input size.

## Edge Cases
- `len(s1) > len(s2)`: initial slice `s2[:len(s1)]` returns the whole `s2`; window != target, loop doesn't run, returns `False` — correct.
- `len(s1) == len(s2)`: only initial window checked; loop range empty — correct.
- Duplicate characters in `s1` (e.g., "aa"): Counter handles multiplicities; deletion of zero-count keys ensures equality works.
- All same character (e.g., s1="aaa", s2="aaaaa"): window counts update correctly; match found.
- No valid permutation: loop exhausts, returns `False`.

## Possible Improvements
The solution is already optimal in time (O(n)) and space (O(1)) for the given constraints. A micro-optimisation: replace `Counter` with a fixed-size list of length 26 and track a `matches` integer to avoid map comparison overhead, but this only improves constant factors. The current code is clear and idiomatic Python.
