# 402. Remove K Digits - Solution Analysis

## Problem Understanding
Given a numeric string `num` and an integer `k`, remove exactly `k` digits to form the smallest possible integer (as a string). The result must not have leading zeros unless the result is exactly "0". Constraints: `1 <= k <= len(num) <= 10^5`, `num` contains only digits and has no leading zeros except for "0" itself. Order of remaining digits must be preserved.

## Approach
**Monotonic Stack (Greedy).** The brute force would try all combinations of removals (exponential). The greedy insight: to minimise the number, the leftmost digits should be as small as possible. We maintain a stack of kept digits that is monotonically non-decreasing; whenever a new digit is smaller than the stack top and we still have removals left, we pop the larger digit — this is always safe because removing a larger earlier digit yields a smaller prefix than any alternative. After processing all digits, any remaining `k` removals are applied to the end (the largest suffix). This yields O(n) time and O(n) space.

## Algorithm
1. Initialise an empty list `stack`.
2. For each `digit` in `num`:
   a. While `k > 0`, `stack` is not empty, and `stack[-1] > digit`:
      - Pop `stack[-1]`.
      - Decrement `k`.
   b. Append `digit` to `stack`.
3. If `k > 0` after the loop, remove the last `k` elements from `stack`.
4. Join `stack` into a string, strip leading `'0'` characters.
5. Return the stripped string if non-empty, otherwise return `"0"`.

## Line-by-Line Explanation
- `stack = []`: stores the digits of the answer being built.
- `for digit in num:`: iterate over each character of the input string.
- `while k and stack and stack[-1] > digit:`: greedy removal condition — we can still remove (`k`), there is a previous digit (`stack`), and that previous digit is larger than the current one, so removing it makes the number smaller.
- `stack.pop()`: discard the larger previous digit.
- `k -= 1`: one removal used.
- `stack.append(digit)`: keep the current digit (after all beneficial pops).
- `if k: stack = stack[:-k]`: if removals remain, the stack is non-decreasing, so dropping from the end removes the largest remaining digits.
- `ans = ''.join(stack).lstrip('0')`: build the result string and remove leading zeros.
- `return ans or '0'`: if stripping leaves an empty string (all zeros removed), return `"0"`.

## Dry Run
Example: `num = "1432219"`, `k = 3`

| Step | digit | stack before | k before | while condition | stack after | k after |
|------|-------|--------------|----------|-----------------|-------------|---------|
| 1    | '1'   | []           | 3        | false           | ['1']       | 3       |
| 2    | '4'   | ['1']        | 3        | false (1<4)     | ['1','4']   | 3       |
| 3    | '3'   | ['1','4']    | 3        | true (4>3)      | ['1','3']   | 2       |
| 4    | '2'   | ['1','3']    | 2        | true (3>2)      | ['1','2']   | 1       |
| 5    | '2'   | ['1','2']    | 1        | false (2==2)    | ['1','2','2']| 1      |
| 6    | '1'   | ['1','2','2']| 1        | true (2>1)      | ['1','2','1']| 0      |
| 7    | '9'   | ['1','2','1']| 0        | false (k=0)     | ['1','2','1','9']| 0   |

After loop `k=0`, no truncation. Join → `"1219"`, no leading zeros → return `"1219"`.

## Complexity
- Time: O(n), where n = len(num). Each digit is pushed once and popped at most once; the while loop across all iterations performs at most n pops total.
- Space: O(n) for the stack, which in the worst case (monotonically increasing input) holds all n digits.

## Edge Cases
- **All digits removed** (`k == len(num)`): loop builds full stack, then `stack[:-k]` becomes empty, `lstrip` yields `""`, returns `"0"` — correct.
- **Leading zeros in result** (`num = "10200", k = 1`): stack becomes `['0','2','0','0']`, `lstrip('0')` → `"200"` — correct.
- **Already non-decreasing** (`num = "12345", k = 2`): no pops inside loop, final truncation removes last two → `"123"` — correct.
- **Single digit** (`num = "5", k = 1`): stack `['5']`, truncation empties it → `"0"` — correct.
- **Large input** (n = 10^5): O(n) time and space fit constraints; no recursion depth issues.

## Possible Improvements
The solution is already optimal in both time and space for the given constraints. A minor readability improvement: rename `stack` to `mono_stack` or `kept` to emphasise the monotonic property, but this is purely stylistic. No algorithmic improvement exists — any correct solution must examine each digit at least once, so Ω(n) is a lower bound.
