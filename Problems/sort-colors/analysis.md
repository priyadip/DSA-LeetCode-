# 75. Sort Colors - Solution Analysis

## Problem Understanding
The input is an array `nums` of length `n` (1 ≤ n ≤ 300) containing only the integers 0, 1, and 2, representing three colors. The task is to sort the array in-place so that all 0s come first, then all 1s, then all 2s. No library sort may be used. The follow-up asks for a one-pass algorithm with O(1) extra space.

## Approach
The solution uses the **Dutch National Flag** algorithm (three-way partitioning), a classic two-pointer pattern for sorting an array with three distinct values. A brute-force approach would count frequencies in one pass and overwrite the array in a second pass (O(n) time, O(1) space but two passes). The chosen approach achieves the follow-up requirement: a single left-to-right scan with three pointers that maintain the invariant that all elements left of `l` are 0, all elements right of `r-1` are 2, and elements between `l` and `c` are 1. The key insight is that when a 2 is swapped from the right, the incoming element is unexamined, so the current pointer must not advance.

## Algorithm
1. Initialize `l = -1` (boundary before the first 0), `r = len(nums)` (boundary after the last 2), `c = 0` (current index).
2. While `c < r`:
   - If `nums[c] == 0`: increment `l`, swap `nums[l]` and `nums[c]`, increment `c`.
   - Else if `nums[c] == 2`: decrement `r`, swap `nums[r]` and `nums[c]` (do not increment `c`).
   - Else (`nums[c] == 1`): increment `c`.
3. Loop terminates when `c` meets `r`; the array is now partitioned into 0s, 1s, 2s in-place.

## Line-by-Line Explanation
- `l = -1`: left boundary, exclusive; all indices ≤ `l` hold 0.
- `r = len(nums)`: right boundary, exclusive; all indices ≥ `r` hold 2.
- `c = 0`: current scanning index.
- `while c < r:`: process until the unexamined region is empty.
- `if nums[c] == 0:`: found a 0 that belongs in the left section.
- `l += 1`: expand the 0-section rightward.
- `nums[l], nums[c] = nums[c], nums[l]`: swap the 0 into the 0-section; the element from `l` (guaranteed to be 1 or 0) moves to `c`.
- `c += 1`: the swapped-in element is known (0 or 1), so advance.
- `elif nums[c] == 2:`: found a 2 that belongs in the right section.
- `r -= 1`: expand the 2-section leftward.
- `nums[r], nums[c] = nums[c], nums[r]`: swap the 2 into the 2-section; the element from `r` is unexamined.
- (no `c += 1`): must re-examine the new `nums[c]`.
- `else:`: `nums[c] == 1`, already in the correct middle section.
- `c += 1`: simply advance.

## Dry Run
Example: `nums = [2,0,2,1,1,0]`

## Complexity
- Time: O(n) — each element is examined at most once; `c` only moves forward, `r` only moves backward, total swaps ≤ n.
- Space: O(1) — only three integer pointers used, no auxiliary arrays.

## Edge Cases
- **All same value** (e.g., `[1,1,1]`): `c` increments to `r` immediately; no swaps.
- **Already sorted** (`[0,0,1,1,2,2]`): 0s and 1s advance `c` and `l`; 2s shrink `r` without moving `c` until done.
- **Reverse sorted** (`[2,2,1,1,0,0]`): each 2 swaps with a 0 from the right, `l` and `r` converge correctly.
- **Single element** (`[0]`, `[1]`, `[2]`): loop runs once or zero times; array unchanged.
- **Minimum length n=1**: handled by loop condition `c < r`.

All cases are reachable under the given constraints (n ≥ 1, values ∈ {0,1,2}).

## Possible Improvements
The solution is already optimal for the constraints: O(n) time, O(1) space, one pass. No asymptotic improvement exists. A minor readability improvement would be renaming `l`, `r`, `c` to `left`, `right`, `curr` (or `p0`, `p2`, `i`) to clarify their roles, but the logic is sound and concise as written.
