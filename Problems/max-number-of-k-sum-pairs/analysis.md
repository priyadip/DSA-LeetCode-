# 1679. Max Number of K-Sum Pairs - Solution Analysis

## Problem Understanding
Given an array `nums` and integer `k`, we repeatedly remove two numbers that sum to `k`. Return the maximum number of such operations. The order of removal doesn't matter; we only need the count of disjoint pairs with sum `k`. Constraints: `n ≤ 10^5`, values up to `10^9`, so an `O(n^2)` pair enumeration is impossible. Duplicates are allowed and each element can be used at most once.

## Approach
**Hash Map / Greedy Single Pass**. The brute force would check all pairs (`O(n^2)`). Instead, we maintain a frequency map of numbers we've seen but not yet paired. For each `x`, we check if its complement `k - x` is already waiting in the map. If yes, we form a pair immediately and consume one complement; if not, we store `x` for future matches. The key insight: **greedily pairing each number with any available complement is optimal because deferring a match never increases the total number of disjoint pairs** — every element can participate in at most one pair, so consuming a complement now cannot hurt a future pairing.

## Algorithm
1. Initialize empty dictionary `freq` and `ans = 0`.
2. For each `x` in `nums`:
   a. Compute `need = k - x`.
   b. If `freq[need] > 0`:
      - Increment `ans`.
      - Decrement `freq[need]`.
   c. Else:
      - Increment `freq[x]`.
3. Return `ans`.

## Line-by-Line Explanation
- `freq = {}`: hash map recording how many times each unpaired value has been seen.
- `ans = 0`: counts completed operations.
- `for x in nums:`: single left-to-right pass.
- `need = k - x`: the value required to pair with `x`.
- `if freq.get(need, 0) > 0:`: a complement is available.
- `ans += 1`: we form a valid pair.
- `freq[need] -= 1`: consume one instance of the complement.
- `else:`: no complement waiting.
- `freq[x] = freq.get(x, 0) + 1`: store `x` for future pairing.
- `return ans`: total operations.

## Complexity
- **Time:** `O(n)` — one pass through `nums`; each hash map operation is `O(1)` average.
- **Space:** `O(n)` — in the worst case (no pairs), `freq` holds all `n` distinct values.

## Edge Cases
- **All elements equal, `k = 2 * x`**: e.g., `[3,3,3,3], k=6`. The map stores the first 3, pairs the second, stores the third, pairs the fourth → `ans = 2 = floor(4/2)`. Correct.
- **No valid pairs**: `ans` stays 0; `freq` accumulates all elements.
- **Single element**: loop runs once, `freq` gets the element, `ans = 0`.
- **Large values (up to 10^9)**: Python integers handle this without overflow.
- **Order independence**: the greedy choice is safe; any valid pairing consumes one of each value, and the total possible pairs for value `v` is `min(count(v), count(k-v))` (or `floor(count(v)/2)` when `v = k/2`), which this algorithm achieves.

## Possible Improvements
The solution is already optimal for the given constraints: `O(n)` time and `O(n)` space is the best possible asymptotic complexity (must read all input). Using `collections.Counter` would be syntactically cleaner but identical in complexity. A two-pointer approach after sorting would be `O(n log n)` time and `O(1)` space, which is slower for large `n`. Variable names (`freq`, `need`, `ans`) are clear and conventional. No redundant passes or structures exist.
