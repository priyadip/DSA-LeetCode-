# 704. Binary Search - Solution Analysis

## Problem Understanding
Given a sorted array of unique integers and a target value, return the index of the target if present, otherwise -1. The array length is at least 1 and at most 10^4, values range from -10^4 to 10^4. The sorted order and uniqueness guarantee that binary search is applicable and the answer is unique when it exists. The required O(log n) runtime rules out linear scan.

## Approach
The solution uses the **binary search** pattern. Because the array is sorted, we can repeatedly halve the search interval by comparing the middle element to the target. If the middle equals the target we are done; if it is larger, the target (if present) must lie in the left half; otherwise it lies in the right half. The brute-force linear scan would be O(n); binary search reduces this to O(log n) by discarding half the remaining elements each iteration. The key insight is that the sorted order lets us eliminate half the search space with a single comparison.

## Algorithm
1. Initialise `l = 0` and `r = len(nums) - 1` as the inclusive bounds of the search interval.
2. While `l <= r`:
   a. Compute `mid = l + (r - l) // 2` (avoids overflow in languages with fixed-width integers).
   b. If `nums[mid] == target`, return `mid`.
   c. If `nums[mid] > target`, set `r = mid - 1` to search the left half.
   d. Else (`nums[mid] < target`), set `l = mid + 1` to search the right half.
3. If the loop exits, the target is not present; return `-1`.

## Line-by-Line Explanation
- `r = len(nums) - 1`: right bound starts at the last index.
- `l = 0`: left bound starts at the first index.
- `while l <= r:`: continue while the interval is non-empty (inclusive bounds).
- `mid = l + (r - l) // 2`: middle index; the formula prevents integer overflow in other languages.
- `if nums[mid] == target:`: found the target.
- `return mid`: return its index immediately.
- `elif nums[mid] > target:`: target is smaller, so it can only be left of mid.
- `r = mid - 1`: shrink right bound to exclude mid and everything right of it.
- `else:`: target is larger, so it can only be right of mid.
- `l = mid + 1`: shrink left bound to exclude mid and everything left of it.
- `return -1`: loop ended without finding target; not in array.

## Dry Run
Example 1: `nums = [-1,0,3,5,9,12]`, `target = 9`

| Step | l | r | mid | nums[mid] | Comparison | Action |
|------|---|---|-----|-----------|------------|--------|
| 1 | 0 | 5 | 2 | 3 | 3 < 9 | l = 3 |
| 2 | 3 | 5 | 4 | 9 | 9 == 9 | return 4 |

Example 2: `nums = [-1,0,3,5,9,12]`, `target = 2`

| Step | l | r | mid | nums[mid] | Comparison | Action |
|------|---|---|-----|-----------|------------|--------|
| 1 | 0 | 5 | 2 | 3 | 3 > 2 | r = 1 |
| 2 | 0 | 1 | 0 | -1 | -1 < 2 | l = 1 |
| 3 | 1 | 1 | 1 | 0 | 0 < 2 | l = 2 |
| 4 | 2 | 1 | — | — | l > r | exit loop, return -1 |

## Complexity
- Time: O(log n), where n = len(nums). Each iteration halves the search interval, so at most ⌈log₂ n⌉ iterations run.
- Space: O(1). Only a constant number of integer variables are used regardless of input size.

## Edge Cases
- Single-element array: loop runs once, correctly returns 0 or -1.
- Target smaller than all elements: `r` moves left until `l > r`, returns -1.
- Target larger than all elements: `l` moves right until `l > r`, returns -1.
- Target at first or last index: found when `mid` lands on that boundary.
- All constraints guarantee non-empty input and unique values, so no duplicate-handling or empty-array logic is needed.

## Possible Improvements
The solution is already optimal for the given constraints: O(log n) time and O(1) space match the theoretical lower bound for comparison-based search in a sorted array. Variable names `l` and `r` are conventional but `left` and `right` would be marginally clearer; no functional change is required.
