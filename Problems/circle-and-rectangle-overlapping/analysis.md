# 1401. Circle and Rectangle Overlapping - Solution Analysis

## Problem Understanding
We must determine whether a circle (given by radius and center) and an axis-aligned rectangle (given by bottom-left and top-right corners) share at least one point. Overlap includes touching boundaries. Coordinates range up to ±10⁴ and radius up to 2000, so an O(1) geometric test is required.

## Approach
The solution uses the **closest-point projection** pattern for an axis-aligned bounding box (AABB). The key insight: the circle overlaps the rectangle iff the distance from the circle center to the closest point on the rectangle is ≤ radius. Brute force would require checking infinitely many points; projecting the center onto the rectangle's extent reduces the problem to a single distance comparison.

## Algorithm
1. Clamp `xCenter` to the interval `[x1, x2]` to obtain the x-coordinate of the rectangle point nearest the circle center.
2. Clamp `yCenter` to the interval `[y1, y2]` to obtain the corresponding y-coordinate.
3. Compute the squared Euclidean distance between this closest point `(x, y)` and the circle center.
4. Return `true` if that squared distance is ≤ `radius²`; otherwise `false`.

## Line-by-Line Explanation
- `x = max(x1, min(xCenter, x2))`: Clamps `xCenter` horizontally to the rectangle's span, yielding the nearest x on the rectangle.
- `y = max(y1, min(yCenter, y2))`: Clamps `yCenter` vertically to the rectangle's span, yielding the nearest y on the rectangle.
- `return (x - xCenter) ** 2 + (y - yCenter) ** 2 <= radius ** 2`: Checks whether the closest rectangle point lies inside or on the circle by comparing squared distance to squared radius.

## Complexity

- Time: O(1) – a constant number of arithmetic operations (min, max, subtraction, multiplication, comparison) independent of input values.
- Space: O(1) – only a few integer variables are stored.

## Edge Cases

- **Circle center inside rectangle**: clamped point equals center, distance 0 ≤ radius² → true.
- **Circle touches rectangle at edge or corner**: distance equals radius → true (example 1).
- **Circle completely outside rectangle**: distance > radius → false (example 2).
- **Rectangle completely inside circle**: closest rectangle point is within radius → true.
- **Large coordinates** (up to ±10⁴): squared values up to 10⁸, well within Python's arbitrary-precision integers.
- **Negative coordinates**: clamping works correctly with negative bounds.

All cases are reachable under the given constraints (radius ≥ 1, x1 < x2, y1 < y2). The solution correctly handles touching as overlapping because the condition uses ≤.

## Possible Improvements

The solution is already optimal for the constraints: O(1) time and O(1) space. The logic is concise, variable names are clear, and there are no redundant passes or structures. Micro-optimisations (e.g., using multiplication instead of `**2`) would not change the complexity and are unnecessary in Python.
