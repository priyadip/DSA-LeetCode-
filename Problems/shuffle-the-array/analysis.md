# 1470. Shuffle the Array - Solution Analysis

## Problem Understanding
The input is an array `nums` of length `2n` logically split into two halves: the first `n` elements (`x_1..x_n`) and the second `n` elements (`y_1..y_n`). The task is to interleave them into a single array `[x_1, y_1, x_2, y_2, ..., x_n, y_n]`. Order matters strictly; duplicates and values are irrelevant beyond their positions. Constraints are small (`n ≤ 500`), so any linear-time, linear-space solution is easily fast enough.

## Approach
The solution uses **direct index mapping** (a form of two-pointer construction without explicit pointers). The brute force would be to build a new list by appending `nums[i]` then `nums[n+i]` in a loop, which is also O(n) but involves dynamic resizing. The chosen approach pre-allocates the exact result array and writes each element to its final position via arithmetic: `x_i` goes to index `2*i`, `y_i` goes to index `2*i+1`. This avoids append overhead and makes the index relationship explicit.  
**Key insight:** The target index of each source element is a simple linear function of its half-index `i`.

## Algorithm
1. Allocate an integer array `ans` of length `2*n` filled with zeros.
2. Loop `i` from `0` to `n-1`:
   - Write `nums[i]` (the `i`-th element of the first half) into `ans[2*i]`.
   - Write `nums[n+i]` (the `i`-th element of the second half) into `ans[2*i+1]`.
3. Return `ans`.

## Line-by-Line Explanation
- `ans = [0]*(2*n)`: Pre-allocates the output array of the exact required size.
- `for i in range(n):`: Iterates over the `n` pairs; `i` is the pair index.
- `ans[2*i] = nums[i]`: Places the `i`-th element from the first half (`x_{i+1}`) at the even position `2*i`.
- `ans[2*i+1] = nums[n+i]`: Places the `i`-th element from the second half (`y_{i+1}`) at the following odd position `2*i+1`.
- `return ans`: Returns the fully populated shuffled array.

## Dry Run
Example: `nums = [2,5,1,3,4,7]`, `n = 3`

| Step | i | nums[i] | nums[n+i] | ans before          | ans after           | Action                          |
|------|---|---------|-----------|---------------------|---------------------|---------------------------------|
| 1    | 0 | 2       | 3         | [0,0,0,0,0,0]       | [2,3,0,0,0,0]       | ans[0]=2, ans[1]=3              |
| 2    | 1 | 5       | 4         | [2,3,0,0,0,0]       | [2,3,5,4,0,0]       | ans[2]=5, ans[3]=4              |
| 3    | 2 | 1       | 7         | [2,3,5,4,0,0]       | [2,3,5,4,1,7]       | ans[4]=1, ans[5]=7              |

Final `ans = [2,3,5,4,1,7]`.

## Complexity
- **Time:** O(n) — the loop runs exactly `n` times, each iteration does O(1) work.
- **Space:** O(n) — the output array `ans` holds `2n` integers; no other significant memory is used.  
Here `n` is the given parameter (half the input length).

## Edge Cases
- **Minimum `n = 1`**: `nums` has two elements; loop runs once, correctly produces `[x_1, y_1]`.
- **All elements equal**: e.g., `[5,5,5,5]` with `n=2` → `[5,5,5,5]`; indices still map correctly.
- **Already interleaved by coincidence**: The algorithm does not check; it blindly writes, which is correct because the specification defines the output purely by position.
- Constraints guarantee `nums.length == 2n` and `n ≥ 1`, so empty input or mismatched lengths cannot occur.

## Possible Improvements
The solution is already optimal for the given constraints: O(n) time and O(n) space are the best possible since every element must be read and written once. A micro-optimisation would be to use a list comprehension `[nums[i//2] if i%2==0 else nums[n+i//2] for i in range(2*n)]`, but that is less readable and offers no asymptotic gain. No material improvement exists.
