# 7. Reverse Integer - Solution Analysis

## Problem Understanding
Given a signed 32-bit integer `x`, reverse its digits. If the reversed value falls outside the 32-bit signed integer range `[-2^31, 2^31 - 1]`, return `0`. Leading zeros in the reversed result are dropped (e.g., `120` → `21`). The sign is preserved. The constraint "environment does not allow 64-bit integers" matters in fixed-width languages but not in Python, which uses arbitrary-precision integers.

## Approach
The solution uses **digit extraction via modulo and integer division** (a math pattern). It processes the absolute value of `x` digit by digit from least significant to most significant, building the reversed number iteratively with `rev = rev * 10 + digit`. The sign is stored separately and reapplied at the end. Overflow is checked once after full reversal. Brute force would convert to string, reverse, and parse back — O(n) time and space. This approach achieves O(log₁₀ x) time and O(1) space. Key insight: the reversed number can be constructed in a single pass by repeatedly shifting the accumulator left (×10) and adding the next extracted digit.

## Algorithm
1. Record the sign of `x`, then work with `abs(x)`.
2. Initialize `reversed_x = 0`.
3. While `x != 0`:
   a. Extract the last digit: `digit = x % 10`.
   b. Append it to `reversed_x`: `reversed_x = reversed_x * 10 + digit`.
   c. Remove the processed digit: `x //= 10`.
4. Reapply the original sign: `reversed_x *= sign`.
5. If `reversed_x` is outside `[-2^31, 2^31 - 1]`, return `0`; otherwise return `reversed_x`.

## Line-by-Line Explanation
- `if x < 0:`: detects negative input to handle sign separately.
- `sign = -1`: stores negative sign for later reapplication.
- `x = abs(x)`: converts `x` to positive so modulo/division work uniformly.
- `else: sign = 1`: stores positive sign for non-negative input.
- `reversed_x = 0`: initializes accumulator for the reversed digits.
- `while x != 0:`: loops until all digits are consumed.
- `digit = x % 10`: extracts the least significant digit (0–9).
- `reversed_x = reversed_x * 10 + digit`: shifts accumulator left and appends the new digit.
- `x //= 10`: discards the processed digit via integer division.
- `reversed_x *= sign`: restores the original sign to the reversed number.
- `if reversed_x < -2**31 or reversed_x > 2**31 - 1:`: checks 32-bit signed integer overflow bounds.
- `return 0`: returns 0 on overflow.
- `else: return reversed_x`: returns the valid reversed integer.

## Dry Run
Trace for Example 2: `x = -123`

| Step | x | digit | reversed_x | Action |
|------|---|-------|------------|--------|
| 0 (init) | 123 | – | 0 | sign = -1, x = abs(-123) = 123 |
| 1 | 123 | 3 | 3 | digit = 123 % 10 = 3; reversed_x = 0*10+3 = 3; x = 123 // 10 = 12 |
| 2 | 12 | 2 | 32 | digit = 12 % 10 = 2; reversed_x = 3*10+2 = 32; x = 12 // 10 = 1 |
| 3 | 1 | 1 | 321 | digit = 1 % 10 = 1; reversed_x = 32*10+1 = 321; x = 1 // 10 = 0 |
| 4 | 0 | – | -321 | loop ends; reversed_x *= sign = -321; bounds check passes; return -321 |

## Complexity
- Time: O(d) where d is the number of digits in x. Since x is a 32-bit signed integer, d ≤ 10, so the loop runs at most 10 times → effectively O(1).
- Space: O(1) – only a constant number of integer variables (sign, reversed_x, digit) are used regardless of input size.

## Edge Cases
- x = 0: loop is skipped, reversed_x stays 0, sign = 1, returns 0. Correct.
- x = -2^31 (-2147483648): abs(x) = 2147483648 (exceeds 2^31-1). Python's arbitrary-precision integers handle this; the loop produces 8463847412, sign makes it -8463847412, final bounds check returns 0. Correct for the problem as judged, though it relies on Python's big integers which violates the "no 64-bit" assumption in a strict sense.
- Trailing zeros (e.g., 120, -120): modulo and integer division naturally drop trailing zeros, yielding 21 and -21 respectively. Correct.
- Maximum positive 32-bit integer (2147483647): reverse is 7463847412 > 2^31-1 → returns 0. Correct.
- Single-digit inputs: loop runs once, returns the same digit (with sign). Correct.

## Possible Improvements
The solution is already optimal in time and space for the given constraints in Python. For strict adherence to the "environment does not allow 64-bit integers" requirement (e.g., in C++/Java), one could add an overflow check inside the loop before `reversed_x = reversed_x * 10 + digit`:
```python
if reversed_x > (2**31 - 1) // 10 or (reversed_x == (2**31 - 1) // 10 and digit > 7):
    return 0
```
(and a symmetric check for the negative bound). This would avoid relying on Python's arbitrary-precision integers and make the algorithm portable to true 32-bit environments. In Python, however, the current approach is clean and accepted.
