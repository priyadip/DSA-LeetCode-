# 152. Maximum Product Subarray - Solution Analysis

## Problem Understanding
Given an integer array `nums`, find the contiguous subarray with the largest product and return that product. The array length is up to 20,000, values range from -10 to 10, and the answer fits in a 32-bit integer. Negatives and zeros are the critical complications: a negative number can flip a large negative product into a large positive one, and zero resets any running product.

## Approach
**Dynamic Programming (Kadane-like with dual state).**  
The brute force would check all O(n²) subarrays, computing each product in O(n) for O(n³) total, or O(n²) with prefix products — too slow for n = 2·10⁴.  
The chosen approach maintains two running values at each index: the maximum product of a subarray ending here (`curr_max`) and the minimum product ending here (`curr_min`). Because multiplying by a negative swaps max and min, keeping both lets us correctly extend the subarray or start fresh at the current element. The global maximum `ans` is updated each step.  
**Key insight:** A subarray's maximum product ending at index i depends only on the maximum and minimum products ending at i-1 and the value at i.

## Algorithm
1. Initialise `curr_max`, `curr_min`, and `ans` to `nums[0]`.
2. Iterate over the remaining elements `x` in `nums[1:]`:
   a. Save `old_max = curr_max` and `old_min = curr_min` (values from previous index).
   b. Compute new `curr_max = max(x, x * old_max, x * old_min)`.
   c. Compute new `curr_min = min(x, x * old_max, x * old_min)`.
   d. Update `ans = max(ans, curr_max)`.
3. Return `ans`.

## Line-by-Line Explanation
- `curr_max = nums[0]`: maximum product of subarray ending at index 0.
- `curr_min = nums[0]`: minimum product of subarray ending at index 0 (needed for future negative flips).
- `ans = nums[0]`: global maximum product seen so far.
- `for x in nums[1:]:`: process each subsequent element.
- `old_max = curr_max`: preserve previous max before overwriting.
- `old_min = curr_min`: preserve previous min before overwriting.
- `curr_max = max(x, x * old_max, x * old_min)`: three choices — start new subarray at x, extend previous max subarray, or extend previous min subarray (which may be negative and flip sign).
- `curr_min = min(x, x * old_max, x * old_min)`: symmetric update for minimum, capturing the most negative product ending here.
- `ans = max(ans, curr_max)`: update global answer with best product ending at current index.
- `return ans`: final result.

## Dry Run
Example: `nums = [2, 3, -2, 4]`

| Step | x   | old_max | old_min | curr_max          | curr_min          | ans | Action                     |
|------|-----|---------|---------|-------------------|-------------------|-----|----------------------------|
| 0    | —   | —       | —       | 2                 | 2                 | 2   | initialise                 |
| 1    | 3   | 2       | 2       | max(3, 6, 6) = 6  | min(3, 6, 6) = 3  | 6   | extend [2] → [2,3]         |
| 2    | -2  | 6       | 3       | max(-2, -12, -6) = -2 | min(-2, -12, -6) = -12 | 6 | start new at -2            |
| 3    | 4   | -2      | -12     | max(4, -8, -48) = 4 | min(4, -8, -48) = -48 | 6 | start new at 4             |

Result: 6 (from subarray [2,3]).

## Complexity
- Time: O(n), one pass over the array; each iteration does O(1) work.
- Space: O(1), only a handful of scalar variables regardless of input size.
Here n = len(nums) ≤ 2·10⁴.

## Edge Cases
- **Single element**: loop is skipped, `ans = nums[0]` returned correctly.
- **All negatives, even count**: e.g., `[-2, -3]` → product 6 captured because `curr_min` tracks -2 then -2 * -3 = 6 becomes `curr_max`.
- **All negatives, odd count**: e.g., `[-2, -3, -4]` → best is 12 from [-3, -4]; algorithm finds it.
- **Zeros**: zero resets both `curr_max` and `curr_min` to 0, then next element starts fresh; global `ans` retains any positive product seen before zero.
- **Mixed with zeros and negatives**: `[-2, 0, -1]` → returns 0 (subarray [0] or empty product not allowed, but 0 > -1, -2).
- **Large n**: O(n) time and O(1) space handle the upper constraint comfortably.

## Possible Improvements
The solution is already optimal in both time (O(n)) and space (O(1)) for this problem. No asymptotic improvement exists. A minor readability tweak: rename `old_max`/`old_min` to `prev_max`/`prev_min` to clarify they belong to the previous index, but this is purely stylistic.
