# 1510. Stone Game IV - Solution Analysis

## Problem Understanding
Two players alternately remove a non-zero perfect square number of stones from a pile of `n` stones. The player who cannot move loses. Alice moves first. We must decide whether Alice has a winning strategy assuming optimal play. The constraint `n ≤ 10^5` allows an `O(n√n)` dynamic programming solution because `√10^5 ≈ 316`, giving about 3·10⁷ operations, which is feasible in Python.

## Approach
The solution uses **Dynamic Programming on game states** (winning/losing positions), a standard pattern for impartial combinatorial games. The key insight: *a position is winning if and only if there exists at least one legal move to a losing position; otherwise it is losing.*  
Brute-force recursion with memoisation would also work but incurs function-call overhead. The iterative bottom‑up DP avoids recursion and computes each state exactly once, which is both simpler and faster for the given limits.

## Algorithm
1. Create a boolean array `dp` of length `n+1` where `dp[i]` indicates whether the current player can force a win with `i` stones. Initialise all entries to `False`; `dp[0] = False` (no stones → current player loses).
2. For each `i` from `1` to `n`:
   - Iterate `j` from `1` while `j*j ≤ i` (all square moves).
   - If `dp[i - j*j]` is `False`, then moving to that state leaves the opponent in a losing position, so set `dp[i] = True` and break the inner loop.
   - If no such `j` is found, `dp[i]` remains `False`.
3. Return `dp[n]`.

## Line-by-Line Explanation
- `dp = [False] * (n + 1)`: Allocates the DP table; `dp[i]` will store the winning status for a pile of `i` stones.
- `for i in range(1, n + 1):`: Processes pile sizes in increasing order so that all smaller states needed for `i` are already computed.
- `j = 1`: Starts with the smallest square (1²).
- `while j * j <= i:`: Enumerates all legal square moves `j²` that do not exceed the current pile `i`.
- `if not dp[i - j * j]:`: Checks whether the state after removing `j²` stones is a losing state for the opponent.
- `dp[i] = True`: Current player can move to that losing state, so `i` is a winning state.
- `break`: No need to check larger squares once a winning move is found.
- `j += 1`: Tries the next square if the current one did not yield a win.
- `return dp[n]`: The answer for the initial pile size `n`.

## Dry Run
Trace for `n = 4` (Example 3):

| Step | i | j | j*j | i - j*j | dp[i - j*j] | dp[i] after | Action |
|------|---|---|-----|---------|-------------|-------------|--------|
| 1    | 1 | 1 | 1   | 0       | False       | True        | set dp[1]=True, break |
| 2    | 2 | 1 | 1   | 1       | True        | False       | j=2 → 4>2, loop ends, dp[2]=False |
| 3    | 3 | 1 | 1   | 2       | False       | True        | set dp[3]=True, break |
| 4    | 4 | 1 | 1   | 3       | True        | –           | continue |
|      |   | 2 | 4   | 0       | False       | True        | set dp[4]=True, break |

Result: `dp[4] = True` → Alice wins.

## Complexity
- **Time:** `O(n√n)`. The outer loop runs `n` times. The inner loop runs up to `√i` times for each `i`, so total iterations ≈ `∑_{i=1}^n √i = O(n√n)`. With `n = 10^5`, this is ~3·10⁷ simple operations.
- **Space:** `O(n)` for the `dp` array of size `n+1`.

## Edge Cases
- `n = 1`: `dp[1]` becomes `True` (Alice removes 1 stone and wins). Handled correctly.
- `n = 2`: Only move is 1 → leaves 1 (winning for opponent), so `dp[2] = False`. Handled correctly.
- Large `n = 10^5`: The loops stay within bounds; Python’s list access is fast enough.
- All positions are reachable under the constraints; no special handling for empty input needed because `n ≥ 1`.

## Possible Improvements
The solution is already asymptotically optimal for the given constraints (`O(n√n)` time, `O(n)` space). A minor constant-factor speedup could be achieved by precomputing all squares `≤ n` once and iterating over that list instead of recomputing `j*j` each time, but the current code is clean and performs well within the limits. No further algorithmic improvement is necessary.
