# 300. Longest Increasing Subsequence - Solution Analysis

## Problem Understanding
Given an integer array `nums`, find the length of the longest strictly increasing subsequence (not necessarily contiguous). The constraints allow up to 2500 elements with values between -10⁴ and 10⁴. The follow-up explicitly asks for O(n log n) time, ruling out the O(n²) DP approach for the optimal solution.

## Approach
The solution uses the **patience sorting / binary search** pattern (often called the "tails" method). This pattern suits LIS because we only need the length, not the actual subsequence, and we can maintain the smallest possible tail value for increasing subsequences of each length. The brute-force DP would be O(n²) by checking all previous elements for each position. The chosen approach reduces this to O(n log n) by keeping a sorted array `tails` where `tails[i]` is the minimum tail of all increasing subsequences of length `i+1`. The key insight: **for any length, a smaller tail is always better because it leaves more room to extend the subsequence with future numbers**.

## Algorithm
1. Initialise an empty list `tails`.
2. Iterate through each number `x` in `nums`:
   a. Find the leftmost index `i` in `tails` where `x` could be inserted to maintain sorted order (using binary search).
   b. If `i` equals the current length of `tails`, append `x` (we found a longer subsequence).
   c. Otherwise, replace `tails[i]` with `x` (we found a smaller tail for the same length).
3. Return the length of `tails`, which equals the LIS length.

## Line-by-Line Explanation
- `tails = []`: Stores the minimum tail value for increasing subsequences of each length; `tails[k]` corresponds to length `k+1`.
- `for x in nums:`: Process each element in order.
- `i = bisect_left(tails, x)`: Binary search for the first position where `x` can be placed; this is the length of the longest subsequence that `x` can extend.
- `if i == len(tails):`: `x` is larger than all current tails, so it extends the longest subsequence found so far.
- `tails.append(x)`: Record the new tail for the new maximum length.
- `else:`: `x` can replace an existing tail to make a subsequence of length `i+1` end with a smaller value.
- `tails[i] = x`: Update the tail for length `i+1` to the smaller value `x`.
- `return len(tails)`: The number of lengths we have tails for equals the LIS length.

## Complexity
- Time: O(n log n), where n = len(nums). Each of the n iterations performs a binary search on `tails` (length ≤ n), costing O(log n).
- Space: O(n) in the worst case (strictly increasing input), as `tails` can grow to size n.

## Edge Cases
- **All equal elements** (e.g., `[7,7,7,7]`): `bisect_left` always returns 0, so `tails` stays `[7]` and returns 1 — correct for strictly increasing requirement.
- **Single element**: Loop runs once, `tails` becomes `[x]`, returns 1.
- **Strictly decreasing input**: Each new element replaces `tails[0]`, final length 1 — correct.
- **Negative numbers**: Handled naturally by comparison; no special treatment needed.
- **Already strictly increasing**: Each element appends, `tails` grows to n, returns n — optimal.
