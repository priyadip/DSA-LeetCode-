# 3483. Unique 3-Digit Even Numbers - Solution Analysis

## Problem Understanding
Given an array of digits (length 3–10, values 0–9), count how many distinct three-digit even integers can be formed such that each occurrence of a digit in the input is used at most once per number and the hundreds digit is non-zero. The small input size (≤10) and digit range (0–9) make exhaustive enumeration feasible.

## Approach
The solution uses **enumeration with a frequency array** (a bounded counting approach). Because the digit domain is fixed at 0–9 and the number length is exactly three, we can iterate over all valid choices for hundreds (1–9), tens (0–9), and units (even digits 0,2,4,6,8), checking availability against a frequency table that is decremented/restored as we pick digits. This avoids generating permutations explicitly and automatically respects the "use each copy once" rule. The brute-force alternative would be to generate all 3-permutations of the input array (up to 10P3 = 720) and filter, which is also fast but less direct. The key insight: the search space is only 9 × 10 × 5 = 450 candidate numbers, so trying each against the frequency counts is optimal and simple.

## Algorithm
1. Build a frequency array `freq[10]` counting occurrences of each digit in `digits`.
2. Initialise answer counter `ans = 0`.
3. Loop `a` from 1 to 9 (hundreds digit, cannot be zero):
   - If `freq[a] == 0`, continue.
   - Decrement `freq[a]` (reserve this digit).
   - Loop `b` from 0 to 9 (tens digit):
     - If `freq[b] == 0`, continue.
     - Decrement `freq[b]`.
     - Loop `c` over even digits 0,2,4,6,8 (units digit):
       - If `freq[c] > 0`, increment `ans` (a valid number `abc` exists).
     - Restore `freq[b]`.
   - Restore `freq[a]`.
4. Return `ans`.

## Line-by-Line Explanation
- `freq = [0] * 10`: frequency table for digits 0–9.
- `for d in digits: freq[d] += 1`: populate counts from input.
- `ans = 0`: accumulator for valid numbers.
- `for a in range(1, 10):`: choose hundreds digit (1–9, no leading zero).
- `if freq[a] == 0: continue`: skip if digit unavailable.
- `freq[a] -= 1`: consume one copy of `a`.
- `for b in range(10):`: choose tens digit (0–9).
- `if freq[b] == 0: continue`: skip if unavailable.
- `freq[b] -= 1`: consume one copy of `b`.
- `for c in range(0, 10, 2):`: choose units digit from even digits only.
- `if freq[c] > 0: ans += 1`: if an even digit remains, the triple (a,b,c) forms a valid number.
- `freq[b] += 1`: backtrack tens digit for next iteration.
- `freq[a] += 1`: backtrack hundreds digit for next iteration.
- `return ans`: total count of distinct valid numbers.

## Complexity
- Time: O(1) — the three nested loops run at most 9 × 10 × 5 = 450 iterations, independent of input size (bounded by constant digit range and fixed length 3). Building the frequency table is O(n) with n ≤ 10, also constant.
- Space: O(1) — the frequency array has fixed size 10.

## Edge Cases
- **All digits odd** (e.g., `[1,3,5]`): inner loop never finds `freq[c] > 0` for even `c`; returns 0 correctly.
- **Duplicate digits** (e.g., `[0,2,2]`): frequency counts allow using `2` twice (202, 220); leading zero prevented by `a` starting at 1.
- **All same even digit** (e.g., `[6,6,6]`): only 666 counted once; frequency decrements ensure three copies needed.
- **Minimum length 3**: guaranteed by constraints, so no special handling for shorter input.
- **Zero in input**: handled naturally; `a` never picks 0, `b` and `c` can.

## Possible Improvements
The solution is already optimal for the given constraints — constant time and space, clear logic, no redundant work. A micro-optimisation would be to precompute the list of even digits with non-zero frequency before the innermost loop, but with only 5 candidates the gain is negligible. No algorithmic improvement is possible because the output itself can be as large as 9×9×5 = 405 (when all digits 0–9 appear sufficiently), so any correct algorithm must essentially enumerate the valid space.
