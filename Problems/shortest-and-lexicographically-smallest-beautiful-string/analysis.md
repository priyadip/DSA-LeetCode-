# 2904. Shortest and Lexicographically Smallest Beautiful String - Solution Analysis

## Problem Understanding
We are given a binary string `s` and an integer `k`. A substring is *beautiful* if it contains exactly `k` occurrences of `'1'`. We must return the lexicographically smallest substring among those with the minimum possible length. If no beautiful substring exists, return an empty string. The constraints (`|s| ≤ 100`) allow quadratic algorithms, but the structure of the problem (exactly `k` ones) lets us restrict attention to windows spanning `k` consecutive ones.

## Approach
The solution uses a **sliding window over the positions of `'1'`**.  
Brute force would examine all `O(n²)` substrings and count ones, costing `O(n³)` with naive counting or `O(n²)` with prefix sums. The key insight is that the shortest substring containing exactly `k` ones must start at a `'1'` and end at a `'1'`, and the `k` ones it contains must be consecutive in the list of all one-positions. Therefore we only need to consider the `m - k + 1` windows of `k` consecutive ones (where `m` is the total number of ones), each giving a candidate substring from the first to the last one in that window. Among these candidates we pick the shortest, breaking ties lexicographically.

## Algorithm
1. Collect the indices of all `'1'` characters in `s` into a list `ones`.
2. If `len(ones) < k`, return `""` (no beautiful substring exists).
3. Initialise `best = ""`.
4. For each `i` from `0` to `len(ones) - k`:
   - `start = ones[i]`, `end = ones[i + k - 1]`.
   - `curr = s[start : end + 1]` (the substring spanning these `k` ones).
   - If `best` is empty, or `len(curr) < len(best)`, or lengths equal and `curr < best` lexicographically, set `best = curr`.
5. Return `best`.

## Line-by-Line Explanation
- `ones = [i for i, c in enumerate(s) if c == '1']`  
  Records the position of every `'1'` in `s`; this compresses the string to only the relevant indices.
- `if len(ones) < k: return ""`  
  Early exit when there are fewer than `k` ones overall.
- `best = ""`  
  Holds the current best candidate; empty string signals no candidate yet.
- `for i in range(len(ones) - k + 1):`  
  Iterates over every window of `k` consecutive ones.
- `curr = s[ones[i]:ones[i + k - 1] + 1]`  
  Extracts the substring from the first one in the window to the last one (inclusive). This is the shortest substring containing exactly those `k` ones.
- `if not best or len(curr) < len(best) or (len(curr) == len(best) and curr < best):`  
  Updates `best` if we have no candidate yet, or `curr` is shorter, or same length but lexicographically smaller.
- `best = curr`  
  Commits the new best candidate.
- `return best`  
  Returns the answer (empty string if never updated).

## Dry Run
Example 1: `s = "100011001"`, `k = 3`.

| Step | i | ones[i] | ones[i+k-1] | curr = s[start:end+1] | len(curr) | best before | best after | Action |
|------|---|---------|-------------|-----------------------|-----------|-------------|------------|--------|
| 1    | 0 | 0       | 5           | "100011"              | 6         | ""          | "100011"   | first candidate |
| 2    | 1 | 4       | 8           | "11001"               | 5         | "100011"    | "11001"    | shorter length |

Result: `"11001"`.

## Complexity
- **Time:** `O(n²)` in the worst case. Collecting `ones` is `O(n)`. The loop runs `m - k + 1 ≤ n` times. Each slice `s[start:end+1]` creates a new string of length up to `n`, so total slicing cost can be `O(n²)`. With `n ≤ 100` this is easily fast enough.
- **Space:** `O(n)` for the `ones` list and the candidate substrings (at most one held at a time, plus the final `best`).

## Edge Cases
- **No beautiful substring:** `len(ones) < k` → returns `""` (Example 3).
- **Multiple minimal-length candidates:** Lexicographic comparison picks the smallest (Example 1: `"11001"` vs `"100011"`).
- **k = 1:** The window size is 1; each candidate is a single `'1'` (length 1). All are equal, so the first `'1'` is returned (lexicographically all `"1"` are equal).
- **All ones:** e.g., `s = "111"`, `k = 2` → windows `[0,1]` and `[1,2]` both yield `"11"`.
- **Already minimal:** The algorithm still checks all windows but correctly keeps the first minimal one if lexicographically smallest.

## Possible Improvements
The solution is already optimal for the given constraints. For larger `n` one could avoid slicing by comparing substrings via indices (using the original string and start/end pointers) to reduce space and time to `O(n)`, but with `n ≤ 100` the current clarity and simplicity are preferable. No material improvement is needed.
