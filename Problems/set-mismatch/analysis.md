# 645. Set Mismatch - Solution Analysis

## Problem Understanding
We are given an array `nums` of length `n` that should contain every integer from `1` to `n` exactly once. Due to an error, one number appears twice (the duplicate) and another number is missing. We must return the duplicate and the missing number as `[duplicate, missing]`. The constraints guarantee `2 ≤ n ≤ 10^4` and `1 ≤ nums[i] ≤ 10^4`, so the input is never empty and values are positive.

## Approach
The solution uses a **Hash Set** to detect the duplicate in a single pass, then computes the missing number arithmetically.  
- **Brute force** would check each number against all others (O(n²)) or sort the array (O(n log n)).  
- The chosen approach inserts each element into a set; the first element already present is the duplicate. Because the set ends up containing every number from `1..n` except the missing one, the missing number equals the expected sum `n(n+1)/2` minus the sum of the set.  
**Key insight:** The set of unique elements is exactly the original set `{1,…,n}` with the missing number removed, so its sum differs from the triangular number by exactly the missing value.

## Algorithm
1. Create an empty set `check`.
2. Store `n = len(nums)`.
3. For each `num` in `nums`:
   - If `num` is already in `check`, record it as `dup`.
   - Otherwise, add `num` to `check`.
4. Compute `expected = n*(n+1)//2`.
5. Compute `mis = expected - sum(check)`.
6. Return `[dup, mis]`.

## Line-by-Line Explanation
- `check = set()`: initializes a hash set for O(1) membership tests.
- `n = len(nums)`: the size of the array, also the maximum value in the original set.
- `for num in nums:`: single pass through the input.
- `if num in check:`: detects the duplicate because it has been seen before.
- `dup = num`: captures the duplicate value (guaranteed to exist exactly once).
- `else: check.add(num)`: records a new unique value.
- `mis = n*(n+1)//2 - sum(check)`: the missing number is the difference between the sum of `1..n` and the sum of the unique elements collected.
- `return [dup, mis]`: produces the required pair.

## Dry Run
Example 1: `nums = [1,2,2,4]`, `n = 4`.

| Step | num | check before | Action                     | check after | dup |
|------|-----|--------------|----------------------------|-------------|-----|
| 1    | 1   | {}           | 1 not in set → add         | {1}         | –   |
| 2    | 2   | {1}          | 2 not in set → add         | {1,2}       | –   |
| 3    | 2   | {1,2}        | 2 in set → dup = 2         | {1,2}       | 2   |
| 4    | 4   | {1,2}        | 4 not in set → add         | {1,2,4}     | 2   |

After loop: `expected = 4*5//2 = 10`, `sum(check) = 7`, `mis = 3`. Return `[2,3]`.

## Complexity
- **Time:** O(n) – one loop over `nums` (O(n)), set operations are O(1) average, and `sum(check)` is O(n).
- **Space:** O(n) – the set `check` holds up to `n` distinct integers.

## Edge Cases
- **Minimum size (n=2):** e.g., `[1,1]` → duplicate `1`, missing `2`; `[2,2]` → duplicate `2`, missing `1`. Works because the set ends up with one element and the arithmetic yields the other.
- **Duplicate appears more than twice:** The problem states exactly one repetition, but if it occurred more often, `dup` would be overwritten with the same value, still correct.
- **Already sorted or reverse sorted:** Order does not affect the set or the sum.
- **All elements equal?** Impossible under constraints because the array must contain numbers from `1..n` with one duplicate and one missing; at least two distinct values must exist.

## Possible Improvements
The solution is already optimal for the given constraints (O(n) time, O(n) space). An O(1) space alternative exists (e.g., marking visited indices by negation or using XOR), but it would complicate the code without asymptotic benefit for `n ≤ 10^4`. The current variable names (`check`, `dup`, `mis`) are clear and the logic is straightforward. No material improvement is needed.
