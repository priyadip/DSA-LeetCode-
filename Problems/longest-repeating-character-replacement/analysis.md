# 424. Longest Repeating Character Replacement - Solution Analysis

## Problem Understanding
Given a string `s` of uppercase letters and an integer `k`, we may change at most `k` characters to any other uppercase letter. We need the length of the longest substring that can become all the same character after at most `k` changes. The string length is up to 10^5, so O(n) or O(n log n) is required; O(n^2) is too slow. Order matters (substring, not subsequence), duplicates are the goal, and `k` can be zero.

## Approach
The solution uses a **sliding window** with a frequency map. The brute force would check every substring and count replacements needed, costing O(n^2). The sliding window maintains a range `[l, r]` where the number of changes required — window length minus the count of the most frequent character in the window — is at most `k`. The key insight: **we never need to shrink the window unless the current window is invalid, and the historical maximum frequency `mf` can be used without decrementing because a stale `mf` only makes the validity check stricter, which cannot cause us to miss a larger valid window already recorded in `answer`.**

## Algorithm
1. Initialise left pointer `l = 0`, empty frequency map `c`, max frequency `mf = 0`, and `answer = 0`.
2. Iterate right pointer `r` from `0` to `len(s)-1`:
   - Increment count of `s[r]` in `c`.
   - Update `mf = max(mf, c[s[r]])`.
   - While the window is invalid — i.e., `(r - l + 1) - mf > k`:
     - Decrement count of `s[l]` in `c`.
     - Increment `l`.
   - Update `answer = max(answer, r - l + 1)`.
3. Return `answer`.

## Line-by-Line Explanation
- `l = 0`: left boundary of the sliding window.
- `c = {}`: dictionary mapping character to its count inside the current window.
- `mf = 0`: tracks the highest frequency of any single character seen in the current window (monotonically non-decreasing).
- `answer = 0`: best window length found so far.
- `for r in range(len(s)):`: expand window to the right one character at a time.
- `c[s[r]] = c.get(s[r], 0) + 1`: add the new character to the frequency map.
- `mf = max(mf, c[s[r]])`: update the historical max frequency; note it never decreases.
- `while (r - l + 1) - mf > k:`: window requires more than `k` replacements, so shrink from left.
- `c[s[l]] -= 1`: remove leftmost character from frequency map.
- `l += 1`: move left boundary rightward.
- `answer = max(answer, r - l + 1)`: record the largest valid window length.

## Dry Run
Example: `s = "AABABBA", k = 1`

| Step | r | s[r] | c (after add) | mf | window len | (len - mf) | l | Action |
|------|---|------|---------------|----|------------|------------|---|--------|
| 1 | 0 | A | {A:1} | 1 | 1 | 0 | 0 | valid, answer=1 |
| 2 | 1 | A | {A:2} | 2 | 2 | 0 | 0 | valid, answer=2 |
| 3 | 2 | B | {A:2,B:1} | 2 | 3 | 1 | 0 | valid, answer=3 |
| 4 | 3 | A | {A:3,B:1} | 3 | 4 | 1 | 0 | valid, answer=4 |
| 5 | 4 | B | {A:3,B:2} | 3 | 5 | 2 > k | 0 | shrink: c[A]=2, l=1 |
|   |   |    | {A:2,B:2} | 3 | 4 | 1 | 1 | valid, answer=4 |
| 6 | 5 | B | {A:2,B:3} | 3 | 5 | 2 > k | 1 | shrink: c[A]=1, l=2 |
|   |   |    | {A:1,B:3} | 3 | 4 | 1 | 2 | valid, answer=4 |
| 7 | 6 | A | {A:2,B:3} | 3 | 5 | 2 > k | 2 | shrink: c[B]=2, l=3 |
|   |   |    | {A:2,B:2} | 3 | 4 | 1 | 3 | valid, answer=4 |

Final answer = 4.

## Complexity
- Time: O(n), where n = len(s). Each character is added once and removed at most once; all map operations are O(1).
- Space: O(1) (or O(26) = O(1)), since the frequency map holds at most 26 uppercase letters regardless of n.

## Edge Cases
- `k = 0`: window only expands while all characters are identical; the algorithm correctly finds the longest run of a single character.
- All characters same: `mf` grows with window, condition never triggers shrink, answer = n.
- `k >= n`: condition never triggers shrink, answer = n (whole string can be made uniform).
- Single character string: loop runs once, answer = 1.
- The stale `mf` does not break correctness: it may cause extra shrinking, but `answer` already captured the larger valid window earlier.

## Possible Improvements
The solution is already optimal in time and space for the given constraints. A minor readability improvement would be to rename `c` to `freq` or `count`, `mf` to `max_freq`, and `l`/`r` to `left`/`right`, but the logic is sound and no algorithmic improvement exists.
