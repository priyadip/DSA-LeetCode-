# 70. Climbing Stairs - Solution Analysis

## Problem Understanding
The problem asks for the number of distinct ways to climb a staircase of `n` steps when each move can be 1 or 2 steps. Input is a single integer `n` (1 ≤ n ≤ 45). Output is the count of distinct sequences of moves that sum to `n`; order matters (1+2 ≠ 2+1). The constraint `n ≤ 45` guarantees the answer fits in a 32-bit integer and makes O(n) time and space easily sufficient.

## Approach
The algorithmic pattern is **Dynamic Programming** (bottom-up tabulation). The problem has optimal substructure: to reach step `n`, the final move must come from step `n-1` (taking 1 step) or step `n-2` (taking 2 steps). Therefore `ways(n) = ways(n-1) + ways(n-2)`, which is the Fibonacci recurrence with base cases `ways(1)=1`, `ways(2)=2`. Brute-force recursion would explore all paths, costing O(2ⁿ) due to overlapping subproblems. DP computes each subproblem once, yielding O(n) time and O(n) space. Key insight: the number of ways to reach step `i` depends only on the two previous steps.

## Algorithm
1. Allocate an array `dp` of length `n+1` initialized to 0, where `dp[i]` will hold the number of ways to reach step `i`.
2. Set base cases: `dp[1] = 1` (one way: a single 1-step) and, if `n ≥ 2`, `dp[2] = 2` (two ways: 1+1 or 2).
3. For each `i` from 3 to `n` inclusive, compute `dp[i] = dp[i-1] + dp[i-2]`.
4. Return `dp[n]`.

## Line-by-Line Explanation
- `dp = [0] * (n + 1)`: Creates the DP table for steps 0..n; index 0 is unused.
- `dp[1] = 1`: Base case — exactly one way to reach step 1.
- `if n >= 2:`: Guards against index error when `n == 1`.
- `dp[2] = 2`: Base case — two ways to reach step 2 (1+1 or 2).
- `for i in range(3, n + 1):`: Iterates over steps 3 through `n`.
- `dp[i] = dp[i - 1] + dp[i - 2]`: Recurrence — ways to reach `i` equals ways to reach `i-1` (then take 1 step) plus ways to reach `i-2` (then take 2 steps).
- `return dp[n]`: Returns the computed answer for the top step.

## Dry Run
Example: `n = 3`

| Step | i | dp[1] | dp[2] | dp[3] | Action |
|------|---|-------|-------|-------|--------|
| init | - | 1     | 2     | 0     | base cases set |
| 1    | 3 | 1     | 2     | 3     | dp[3] = dp[2] + dp[1] = 2+1=3 |
| end  | - | 1     | 2     | 3     | return dp[3] = 3 |

## Complexity
- Time: O(n), because the loop runs `n-2` times and each iteration does O(1) work.
- Space: O(n), because the `dp` array stores `n+1` integers. (Can be reduced to O(1) with two variables.)

## Edge Cases
- `n = 1`: The `if n >= 2` guard skips `dp[2]`, the loop is empty, returns `dp[1] = 1`. Correct.
- `n = 2`: Base cases set, loop empty, returns `dp[2] = 2`. Correct.
- `n = 45` (maximum): Loop runs 43 times; Python integers handle the result (Fibonacci(46) ≈ 1.8×10⁹) without overflow. Correct.
- Constraints guarantee `n ≥ 1`, so `n = 0` or empty input are not applicable.

## Possible Improvements
The solution is correct and optimal in time for the given constraints. Space can be reduced from O(n) to O(1) by keeping only the last two values (`prev2`, `prev1`) instead of the full array, since each step depends solely on the previous two. This is the standard optimization for Fibonacci-like DP and would make the memory usage constant while preserving O(n) time. The current O(n) space is acceptable for `n ≤ 45`, but the O(1) version is more idiomatic for this pattern.
