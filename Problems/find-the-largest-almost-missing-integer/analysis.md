# 3471. Find the Largest Almost Missing Integer - Solution Analysis

## Problem Understanding
We are given an array `nums` and an integer `k`. A value `x` is *almost missing* if it appears in **exactly one** contiguous subarray of length `k`. We must return the largest such `x`, or `-1` if none exists. The constraints are small (`n ≤ 50`, values `0…50`), but the solution should still be derived from the structural properties of subarrays rather than brute force.

## Approach
The solution uses a **case analysis** based on the value of `k`, which is the algorithmic pattern here (analytical reduction to boundary elements).  
- **Brute force** would enumerate all `n‑k+1` subarrays, count how many subarrays contain each value, and pick the maximum with count `1`. That would be `O(n·k)` time and `O(n)` space – acceptable for `n=50` but unnecessary.  
- The **key insight** is that for `1 < k < n`, only the first and last elements of the array can possibly belong to exactly one subarray of size `k`; every interior element belongs to at least two such subarrays. Therefore the candidates are at most `nums[0]` and `nums[-1]`, and they are valid only when their overall frequency in `nums` is exactly `1`.

## Algorithm
1. Build a frequency counter `c` of all numbers in `nums`.
2. **If `k == 1`**: each element forms its own subarray. A number appears in exactly one subarray iff its frequency is `1`. Return the maximum such number (or `-1`).
3. **Else if `k == len(nums)`**: there is only one subarray (the whole array). Every element appears in that one subarray, so the answer is simply `max(nums)`.
4. **Else (`1 < k < n`)**: only `nums[0]` and `nums[-1]` can be almost missing. Check each; keep those with frequency `1`. Return the maximum of the kept values, or `-1` if none.

## Line-by-Line Explanation
- `c = Counter(nums)`: builds a hash map `value → frequency` for the whole array.
- `if k == 1:`: handles the case where every subarray has length 1.
- `return max((x for x in nums if c[x] == 1), default=-1)`: filters numbers that occur exactly once and returns the largest; `default=-1` covers the “no such number” case.
- `elif k == len(nums):`: handles the case where the only subarray is the entire array.
- `return max(nums)`: every element qualifies, so the maximum element is the answer.
- `else:`: the remaining case `1 < k < n`.
- `return max((x for x in (nums[0], nums[-1]) if c[x] == 1), default=-1)`: considers only the two boundary elements, keeps those with frequency `1`, and returns the larger (or `-1`).

## Complexity
- **Time:** `O(n)` – building the counter scans `nums` once; the subsequent `max` operations scan at most `n` elements (in the `k==1` branch) or a constant number (other branches).
- **Space:** `O(n)` – the counter stores at most `n` distinct values (bounded by 51 here, but `O(n)` in general).

## Edge Cases
- **`k = 1` with all duplicates** (Example 3): correctly returns `-1`.
- **`k = n`**: returns `max(nums)` even if duplicates exist, because the single subarray contains every element.
- **`1 < k < n` with `nums[0] == nums[-1]`**: frequency of that value is at least 2, so neither qualifies → returns `-1`.
- **Single-element array (`n=1`)**: then `k=1` (since `1 ≤ k ≤ n`). The `k==1` branch runs, frequency is 1, returns that element – correct.
- **Values at boundaries appearing elsewhere**: frequency > 1 eliminates them, as required (they would belong to multiple subarrays).

All cases are reachable under the given constraints.
