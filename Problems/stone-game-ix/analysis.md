# 2029. Stone Game IX - Solution Analysis

## Problem Understanding
Two players alternately remove stones from an array. A running sum of removed stones is maintained; if after a move the sum becomes a multiple of 3, the player who just moved loses. If all stones are removed without the sum ever being a multiple of 3, Bob wins. Both play optimally. The input is an array of positive integers (length up to 10^5). The output is a boolean indicating whether Alice (first player) has a winning strategy. The constraints demand an O(n) or O(n log n) solution.

## Approach
The solution uses a **combinatorial game theory** analysis that reduces the game to a simple condition on the counts of stones modulo 3. The brute-force approach would explore all move sequences (exponential). The key insight is that only the remainders modulo 3 matter: stones with remainder 0 do not change the sum modulo 3, while remainders 1 and 2 act as +1 and -1 (mod 3) respectively. Optimal play can be characterised entirely by the parity of the count of remainder-0 stones and the difference between the counts of remainder-1 and remainder-2 stones. This yields a closed-form O(n) decision rule.

## Algorithm
1. Count stones by remainder modulo 3: `c0` (remainder 0), `c1` (remainder 1), `c2` (remainder 2).
2. If `c0` is even:
   - Alice wins **iff** both `c1 > 0` and `c2 > 0`.
3. If `c0` is odd:
   - Alice wins **iff** `abs(c1 - c2) > 2`.
4. Return the boolean result.

## Line-by-Line Explanation
- `c0 = c1 = c2 = 0`: Initialise counters for the three remainder classes.
- `for stone in stones:`: Iterate over each stone once.
- `r = stone % 3`: Compute the remainder when divided by 3.
- `if r == 0: c0 += 1`: Increment the count of remainder-0 stones.
- `elif r == 1: c1 += 1`: Increment the count of remainder-1 stones.
- `else: c2 += 1`: Increment the count of remainder-2 stones (the only remaining case).
- `if c0 % 2 == 0:`: Branch on the parity of the remainder-0 count.
- `return c1 > 0 and c2 > 0`: For even `c0`, Alice wins exactly when both non-zero remainders are present.
- `return abs(c1 - c2) > 2`: For odd `c0`, Alice wins exactly when the difference between the two non-zero counts exceeds 2.

## Complexity
- **Time:** O(n), where n = len(stones). A single pass counts remainders; all other operations are O(1).
- **Space:** O(1). Only three integer counters are used, independent of input size.

## Edge Cases
- **All stones ≡ 0 (mod 3):** `c1 = c2 = 0`. Both branches return `false` (Alice loses on first move because the sum becomes a multiple of 3 immediately). Correct.
- **Only one non-zero remainder present (e.g., only remainder 1):**  
  - If `c0` even: `c2 = 0` → `false`.  
  - If `c0` odd: `abs(c1 - 0) > 2` requires `c1 ≥ 4` for Alice to win. This matches the known theory: with an odd number of “neutral” (remainder 0) stones, the first player can force a win only if the imbalance between the two active remainders is large enough.
- **Single stone (n = 1):** Handled by the same logic; e.g., `[2]` gives `c0=0, c1=0, c2=1` → even `c0` → `false`. Alice loses because after her move the sum is 2 (not divisible by 3) and no stones remain, so Bob wins automatically. Correct.
- **Maximum input size (10^5):** O(n) time and O(1) space easily satisfy the limits.
