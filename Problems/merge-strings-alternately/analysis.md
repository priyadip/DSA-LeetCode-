# 1768. Merge Strings Alternately - Solution Analysis

## Problem Understanding
Given two strings `word1` and `word2`, we must interleave their characters starting with `word1[0]`, then `word2[0]`, then `word1[1]`, etc. Once the shorter string is exhausted, the remaining suffix of the longer string is appended unchanged. Both strings have length 1–100 and contain only lowercase letters, so no empty-input or encoding concerns exist.

## Approach
The solution uses the **two-pointer / zip iteration** pattern. The brute-force approach would manually manage two indices and a while-loop, costing O(m+n) time and O(m+n) space for the result. Using Python's built-in `zip` handles the alternating phase cleanly by pairing characters up to the shorter length, then a single slice-and-extend appends the leftover tail. The key insight: `zip` stops at the shorter iterable, so the remainder is exactly the slice starting at the shorter length.

## Algorithm
1. Initialise an empty list `ans` to collect characters.
2. Store lengths `m = len(word1)`, `n = len(word2)`.
3. Iterate over `zip(word1, word2)` yielding pairs `(ch1, ch2)` up to `min(m, n)`:
   - Append `ch1` then `ch2` to `ans`.
4. If `m > n`, extend `ans` with `word1[n:]` (the unused suffix of `word1`).
5. If `n > m`, extend `ans` with `word2[m:]` (the unused suffix of `word2`).
6. Join `ans` into a single string and return it.

## Line-by-Line Explanation
- `ans = []`: accumulator for output characters; list avoids quadratic string concatenation.
- `m = len(word1)` / `n = len(word2)`: cache lengths for the tail-slice indices.
- `for ch1, ch2 in zip(word1, word2):`: iterate pairwise over both strings up to the shorter length.
- `ans.append(ch1)` / `ans.append(ch2)`: add the alternating characters in order.
- `if m > n: ans.extend(word1[n:])`: append remaining characters of `word1` when it is longer.
- `if n > m: ans.extend(word2[m:])`: append remaining characters of `word2` when it is longer.
- `return ''.join(ans)`: convert list of characters to the final merged string.

## Dry Run
Example 2: `word1 = "ab"`, `word2 = "pqrs"` (m=2, n=4)

| Step | ch1 | ch2 | ans (list)          | Action                     |
|------|-----|-----|---------------------|----------------------------|
| 1    | 'a' | 'p' | ['a', 'p']          | append pair from zip       |
| 2    | 'b' | 'q' | ['a', 'p', 'b', 'q']| append pair from zip       |
| —    | —   | —   | —                   | zip exhausted (min=2)      |
| 3    | —   | —   | ['a','p','b','q','r','s'] | `n>m` true, extend `word2[2:]` = "rs" |
| 4    | —   | —   | "apbqrs"            | join and return            |

## Complexity
- Time: O(m + n), because `zip` visits `min(m,n)` pairs and each `extend` copies the remaining `|m-n|` characters once.
- Space: O(m + n) for the output list `ans` (the result itself); auxiliary space is O(1) beyond that.

## Edge Cases
- **Equal lengths** (`m == n`): neither `if` branch triggers; `zip` consumes all characters, result is perfect alternation.
- **One string length 1, other length 100** (max constraint): `zip` runs once, the longer string's 99-character suffix is extended in one slice operation — still O(m+n).
- **All characters identical** (e.g., `"aaa"`, `"aa"`): algorithm behaves identically; no special handling needed.
- Constraints guarantee `m,n ≥ 1`, so empty-string cases are impossible and not considered.

## Possible Improvements
The solution is already optimal for the given constraints — O(m+n) time and space is the theoretical lower bound since every character must appear in the output. A minor readability tweak: rename `m,n` to `len1,len2` or `n1,n2` to avoid single-letter names, but this is purely stylistic. No algorithmic improvement exists.
